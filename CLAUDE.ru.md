# Работа в этом репозитории

[English version](CLAUDE.md)

Заметки для агента, который здесь работает. Сами правила живут в
[CONTRIBUTING.ru.md](CONTRIBUTING.ru.md), и большинство из них проверяет CI. Этот файл
существует потому, что «прочитать правила» — шаг, который пропускают, и одно из них пропустили
уже не в первый раз.

## Прочитать до того, как открывать pull request

**Pull request, меняющий `src/`, либо правит документацию, либо говорит, почему не правит.**
Иначе падает `.github/workflows/documentation.yml`. Он читает тело pull request, поэтому
зелёная сборка — ещё не весь ответ, и он перезапускается при правке тела.

По порядку:

1. **Найти, что изменение сделало неверным.** Искать в `docs/`, `README.ru.md`, `SECURITY.ru.md`
   и `CONTRIBUTING.ru.md` команду, строку, процедуру или поведение, которых коснулись. Эти
   документы описывают текущее состояние продукта как факт; предложение, переставшее быть
   правдой, — это дефект, и заметить его нужно сейчас, а не релизом позже.
2. **Поправить найденное — и его пару.** Каждый документ существует дважды, `name.md` и
   `name.ru.md`, и каждый в первых строках ссылается на свою пару. Документ на одном языке
   считается незаконченным.
3. **Только если править было нечего**, поставить в теле pull request отдельную строку:

   ```
   Docs: none — internal refactor, no described behaviour changed
   ```

Шаг 3 не отменяет шага 1. «Документацию посмотрели, и ей ничего не нужно» и «про документацию
забыли» снаружи выглядят одинаково; эта строка — единственное, что их различает, поэтому она
должна быть правдой в момент, когда её пишут.

## Красный CI не оставляют

Красная проверка — дефект изменения, в том числе когда это проверка документации. Не открывать
следующий pull request поверх красного и не считать упавшую проверку чужой заботой.

Обе проверки важны и падают по разным причинам:

| Проверка | Где идёт | Падает, когда |
| --- | --- | --- |
| `build-and-test` | Windows | решение не собирается или падает тест |
| `documentation-considered` | Linux | `src/` изменён, документация — нет, и тело не говорит почему |

## Ветки и pull request'ы

Одна тема на ветку, ветка — от `main`. Две темы в одной ветке нельзя ни отревьюить по
отдельности, ни откатить по отдельности. Не стекать один pull request на другой: при удалении
базовой ветки на мерже GitHub закрывает второй, а не переносит его на `main`. Если два
изменения трогают один файл — влить первое и сделать ребейз второго.

Имя ветки — по типу работы: `fix/`, `feature/`, `test/`, `docs/`, `refactor/`, `chore/`, дальше
короткое имя словами: `fix/version-line-holds`, а не номер issue.

## Как гонять тесты

```powershell
dotnet test LocalAi.slnx --configuration Release --max-parallel-test-modules 1 --timeout 20m
```

Это то, что гоняет CI, и это ответ перед pull request. Пока идёт работа, быстрее один проект —
`dotnet test tests/<name>/<name>.csproj --configuration Release` или его собранный exe с
`-class <полное.имя.типа>`. Сборка и тесты никогда не запускают Ollama, поэтому машина без GPU
прогоняет набор целиком; несколько тестов пропускают себя там, где платформа их не держит.

Тест не проверяет, насколько быстра машина. Ждать наступления условия, а не истечения срока:
срок, в который может не уложиться корректный прогон, ничего не проверяет, а в отчёте выглядит
как поломка проверяемого кода.

## Что печатает продукт

Каждую строку, которую печатает программа, выбирает машина читателя: по умолчанию английская,
на русской системе — русская, и снова английская там, где перевода нет. Строки лежат парами
`.resx` в каталоге `Resources/` той сборки, которая их печатает, и достаются через
`TextCatalogue`; тест на полноту не пропускает язык, в котором переведена лишь часть ключей.

Не переводится никогда и ни на каком языке: команды, имена параметров, идентификаторы, значения
enum, статусные токены, форматы обмена, пути и атрибуты `[Description]` у MCP-инструментов.
Числа, длительности и даты остаются инвариантными везде — эти строки агенты цитируют дословно,
а тесты разбирают.

Формулировки, вёрстку и то, что переводить не следует, решает агент `ux-designer` из
[`.claude/agents/ux-designer.md`](.claude/agents/ux-designer.md), а не исполнитель. Дать ему
файл и уже принятые правила и попросить отметить то, что должно остаться как есть.

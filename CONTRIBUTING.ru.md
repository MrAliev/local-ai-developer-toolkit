# Участие в разработке

[English version](CONTRIBUTING.md)

Спасибо, что заглянули. Это рабочий инструмент, а не фреймворк, поэтому правила ниже короткие —
и соблюдаются.

## Как собрать решение

```powershell
dotnet restore LocalAi.slnx
dotnet test LocalAi.slnx --configuration Release --no-restore
```

Нужен .NET 10 SDK. Сборка и модульные тесты никогда не запускают Ollama, поэтому прогнать набор
можно и на машине без видеокарты; несколько тестов пропускают себя сами, когда платформа их не
поддерживает, — это нормально.

## Требования к изменениям

**Одна тема на pull request, ветка — от `main`.** Две темы в одной ветке нельзя ни отревьюить по
отдельности, ни откатить по отдельности. Не стекайте один pull request на другой: при удалении
базовой ветки на мерже GitHub закрывает второй, а не переносит его на `main`. Если два изменения
трогают один файл — влейте первое и сделайте ребейз второго.

**Тесты идут вместе с поведением и никогда не проверяют, насколько быстра машина.** Ждите
наступления условия, а не истечения срока; берите дочерним процессом небольшую программу под
задачу, а не интерпретатор с непредсказуемым временем запуска; поиск зависаний оставьте
таймауту прогона, который CI задаёт для всего решения. Срок, в который может не уложиться
корректный прогон, ничего не доказывает и выглядит в отчёте как поломка проверяемого кода. Это не
вопрос вкуса: именно так тесты в этом репозитории ошибались чаще всего.

**К Ollama обращаются только через общий broker.** Никаких `localhost:11434` и никакого запуска
бинарника `ollama` из инструмента. Broker — это то, что сохраняет корректность порядка,
дедупликации, аренд, heartbeat и восстановления, когда одновременно работают несколько клиентов.

**Пространства имён, команды, пути рантайма и версии пакетов остаются как есть**, если изменение
не существует специально ради их обновления.

**Комментарии объясняют почему, а не что.** Что делает код — видно из кода. Комментарий
оправдывает своё место тем, что фиксирует причину — обычно ту поломку, из-за которой всё и
устроено именно так.

## Документация

Каждый документ существует дважды: `name.md` по-английски и `name.ru.md` по-русски, и каждый
в первых строках ссылается на свою пару. Это относится к планам и проектным запискам в
`docs/superpowers/` ровно так же, как к README. Документ на одном языке — незаконченный
документ.

Документация репозитория — UTF-8 без BOM, с окончаниями строк Windows CRLF.

## Релизы

Релиз выпускает мейнтейнер одной командой, в два захода:

```powershell
localai-release-signer release --version 0.1.46            # заметки, затем pull request
localai-release-signer release --version 0.1.46 --publish  # сборка, подпись, проверка, тег, публикация
```

Вторая половина не запустится, пока дерево не чистое, коммит не на `main`, CI не зелёный именно
на этом коммите, а подписанный манифест не согласуется с публикуемой версией — включая наличие
списка моделей, без которого установка не поставила бы ни одной.

## Чего ждать от ревью

Сначала корректность, затем — объясняет ли изменение следующему читателю, зачем оно существует.
Вопросов про режимы отказа будет больше, чем про форматирование.

## Поведение

Спор о работе — смысл ревью; остальное описано в [кодексе поведения](CODE_OF_CONDUCT.ru.md),
включая то, как сообщить о проблеме приватно, не публикуя ни одной из сторон свой адрес.

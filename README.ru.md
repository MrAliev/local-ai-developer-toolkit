# LocalAi

LocalAi — нейтральное решение .NET для локальных инструментов ИИ, предназначенных для
разработчиков. Оно объединяет существующие исходники и тесты CodeSearch и LocalLm в одном
репозитории, сохраняя их пространства имён, версии пакетов и поведение во время выполнения.

Репозиторий содержит исходный код и явные opt-in-команды настройки. Простое открытие
репозитория ничего не регистрирует и не изменяет. `localai sync` создаёт проверенное поколение
локальной основной ветки и точные overlays рабочих деревьев; `localai hooks install` устанавливает общие
chained Git hooks только после одобрения внешней настройки владельцем.

## Проекты

| Проект | Назначение |
|---|---|
| `src/CodeSearch.Core` | Разбиение кода на фрагменты, эмбеддинги через Ollama, хранение индекса и гибридный поиск. |
| `src/CodeSearch.Cli` | Интерфейс командной строки для построения, поиска и проверки индексов кода. |
| `src/CodeSearch.Mcp` | stdio MCP-сервер, предоставляющий операции CodeSearch. |
| `src/LocalLm.Core` | Клиент чата Ollama, выполнение локальных задач, метаданные изображений и оценка токенов. |
| `src/LocalLm.Mcp` | stdio MCP-сервер, предоставляющий операции LocalLm. |
| `src/LocalAi.Broker` | Надёжная общая FIFO-очередь и единственный транспорт Ollama. |
| `src/LocalAi.Cli` | Синхронизация репозитория, совместимый транспорт и установка hooks. |
| `tests/CodeSearch.Tests` | Модульные тесты CodeSearch. |
| `tests/LocalLm.Tests` | Модульные тесты LocalLm. |

## Предварительные требования

- .NET 10 SDK
- Доступ к `https://api.nuget.org/v3/index.json` для чистого восстановления пакетов
- Ollama требуется только при запуске функций, обращающихся к локальным моделям; сборка и
  модульные тесты её не запускают

Файл `NuGet.config` намеренно очищает унаследованные источники пакетов, чтобы посторонние
приватные репозитории пакетов не становились зависимостями сборки.

## Сборка и тестирование

Из корня репозитория:

```powershell
dotnet restore LocalAi.slnx
dotnet build LocalAi.slnx --configuration Release --no-restore
dotnet test LocalAi.slnx --configuration Release --no-build
```

Базовая проверка одной командой:

```powershell
dotnet test LocalAi.slnx --configuration Release
```

## Публикация

Публикуйте только те исполняемые проекты, которые необходимы:

```powershell
dotnet publish src/CodeSearch.Cli/CodeSearch.Cli.csproj --configuration Release --output publish/CodeSearch.Cli
dotnet publish src/CodeSearch.Mcp/CodeSearch.Mcp.csproj --configuration Release --output publish/CodeSearch.Mcp
dotnet publish src/LocalLm.Mcp/LocalLm.Mcp.csproj --configuration Release --output publish/LocalLm.Mcp
```

Каталог `publish/` игнорируется. Публикация не регистрирует полученные исполняемые файлы
в клиентах ИИ.

## Особенности выполнения

- CodeSearch и LocalLm отправляют всю работу моделей через надёжную FIFO-очередь LocalAi.
- Неизменяемая база строится из локальной `dev`, если она существует, иначе — из локальной `main`;
  каждый worktree получает точный overlay, привязанный к generation/tree/dirty-content,
  в `%LOCALAPPDATA%\LocalAi`. Выбранная основная ветка сохраняется в manifest репозитория.
- CodeSearch канонизирует индексируемый текст в Windows CRLF в памяти для хеширования, разбиения
  на чанки и эмбеддинга. Исходные файлы никогда не перезаписываются, а изменение версии
  нормализации создаёт новую неизменяемую базовую generation. Существующие векторы
  переиспользуются только при совпадении модели, размерности, форматов чанков и индекса, а также
  контракта нормализации.
- Общие hooks post-commit, post-merge, post-rewrite и post-checkout вызывают `localai sync`.
- Прямые agent-facing endpoints Ollama запрещены; строго ограниченная команда совместимости
  `native` также всегда проходит через broker.
- MCP-проекты используют транспорт stdio; стандартный вывод предназначен только для сообщений
  протокола.
- Не добавляйте в Git созданные индексы, журналы, файлы процессов и другое рабочее состояние.
- `RuntimeAcl.Ensure` применяет и проверяет права доступа для каждого пути за один проход,
  поэтому его безопасно вызывать параллельно из нескольких клиентских процессов (например, когда
  Claude и Codex одновременно подключаются к брокеру) — без ложного `Runtime ACL verification
  failed`. Раньше метод дважды обходил дерево (сначала применял права везде, затем заново обходил
  и проверял везде), из-за чего путь, созданный параллельным процессом между двумя обходами,
  попадал под проверку, хотя права на него так и не были применены.

## Правила разработки

- Сохраняйте существующие пространства имён и версии пакетов, если их изменение не одобрено
  отдельно.
- Добавляйте тесты вместе с изменениями поведения и запускайте полную базовую проверку решения
  перед публикацией.
- Поддерживайте этот русский файл и английский `README.md` синхронизированными.

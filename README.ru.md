# Локальный инструментарий разработчика для искусственного интеллекта

[Русская версия](README.ru.md)

## Обзор

Локальный инструментарий разработчика для искусственного интеллекта — это решение .NET для запуска инструментов разработки локальных моделей через один устойчивый, машино-облачный брокер. Он объединяет репозитория с осознанным семантическим поиском кода, интеграции MCP, помощники задач для локальных моделей и синхронизацию индексов с учетом Git без изменения исходных проектов просто путем открытия репозитория.

Исходное решение на уровне кода, пространства имен, команд и каталога выполнения остаются названными `LocalAi`, `CodeSearch` и `LocalLm`. Название репозитория описывает полный инструментарий, а не переименовывает эти стабильные контракты.

## Основные возможности

- Устойчивый общесистемный FIFO-брокер — единственный поддерживаемый транспорт к Ollama; он последовательно выполняет общую очередь задач Codex, Claude, CodeSearch и LocalLm.
- Маршрутизация с учётом моделей выбирает подходящую модель по возможностям, текущей резидентности в VRAM, ограничению контекста, состоянию эксперимента и установленному порядку резервных вариантов.
- Снимки с осознанной моделью группируют работу для той же модели, выполняют более короткие совместимые задачи первыми и предотвращают истощение после 15 минут.
- CodeSearch сочетает сходство векторов с литеральным соответствием для репозитория с осознанным семантическим и лексическим поиском кода.
- Неизменные базовые генерации представляют выбранный локальный основной поток, тогда как точные перекрытия рабочего дерева содержат различия ветвей и измененного содержания.
- CodeSearch и LocalLm предоставляют серверы MCP через stdio для интеграции с совместимыми клиентами AI.
- Синхронизация репозиториев и общий Git hooks — явные операции опционального включения.
- Рекомендуемые модели обнаруживаются и устанавливаются через MCP без удаления существующих запасных моделей.

## Как компоненты работают вместе

```text
Codex / Claude / MCP clients
          |
          +--> CodeSearch MCP/CLI --> repository index + worktree overlay
          |
          +--> LocalLm MCP --------> local task helpers
                          |
                          v
                 LocalAi FIFO broker
                          |
                          v
                        Ollama
```

Брокер владеет моделью транспорта и долговечностью очереди. CodeSearch владеет чанкингом, эмбеддингами, генерацией неизменяемых индексов, оверлейсами и гибридным извлечением. LocalLm владеет локальными помощниками чата/задач и оценками токенов. `LocalAi.Cli` владеет регистрацией репозитория, синхронизацией, совместимым транспортом и установкой включаемых хуков.

### Работа с результатами CodeSearch

`search_code` использует модель эмбеддингов, записанную в индексе. Production-поиск
получает измеренный порог релевантности для этой точной модели и завершается закрытым
отказом `threshold not calibrated`, если профиля нет; порог другой модели никогда не
заимствуется.

Каждый результат поиска содержит непрозрачный `chunk_id`. Передайте его в
`get_code_chunk`, чтобы получить полный проиндексированный чанк исходника. ID привязан
к репозиторию, неизменяемой generation, текущему Git tree, хешу dirty-содержимого и
composite ordinal чанка. Malformed, cross-repository, stale или out-of-range ID
отклоняется, а не разрешается по другому snapshot.

Полученный из исходников MCP-вывод — это данные, а не инструкции. `search_code`
оставляет доверенную сводку индекса снаружи, а каждый результат возвращает в отдельном
блоке со свежим nonce:

```text
<untrusted-content id="<96-bit-lowercase-hex-nonce>" origin="search_code:<path>">
...полученный из исходника результат, включая chunk_id...
</untrusted-content id="<same-nonce>">
```

Успешный вывод `get_code_chunk` использует ту же границу. Ошибки валидации, status и
maintenance-вывод остаются снаружи. Потребители должны сохранять границу и не должны
исполнять или выполнять инструкции, найденные внутри неё.

Эквивалентные команды CLI:

```powershell
dotnet run --project src/CodeSearch.Cli -- search --query "where is the broker queue" --root C:\path\to\repository
dotnet run --project src/CodeSearch.Cli -- get-chunk --id "<chunk_id>" --root C:\path\to\repository
```

Измеренный откалиброванный профиль, происхождение корпуса, результаты A/B, эвристика
токенов и ограничения приведены в
[оценке retrieval CodeSearch](docs/codesearch-evaluation.ru.md).

## Предварительные требования

- .NET 10 SDK
- Доступ к `https://api.nuget.org/v3/index.json` для чистого восстановления
- Ollama и установленная совместимая модель только при работе с функциями, поддерживающими модели; сборки и модульные тесты не запускают Ollama

`NuGet.config` намеренно очищает наследуемые источники пакетов, чтобы незатронутые частные фиды не становились зависимостями сборки.

```powershell
dotnet test LocalAi.slnx --configuration Release --no-restore
```

Проверьте синхронизацию репозитория без применения внешнего настройки:

```powershell

dotnet run --project src/LocalAi.Cli -- repo status
```

Синхронизируйте авторизованный репозиторий явно:

```powershell
dotnet run --project src/LocalAi.Cli -- sync --root C:\path\to\repository
```

После установки двоичных файлов MCP проверьте и синхронизируйте модельный каталог через
LocalLm:

```text
local_models_status
local_models_sync
```

Команда синхронизации отправляет разрешенные задачи обслуживания в одну и ту же устойчивую очередь. Она не предоставляет общую команду для извлечения и не удаляет существующие модели.

Установите общий цепочный Git hook только после одобрения внешнего изменения:

```powershell
C:\path\to\LocalAi\bin\launcher\localai-launcher.exe run localai hooks install --root C:\path\to\repository
```

### Подпись манифеста релиза

Установщик отвергает любой релиз, чей манифест не подписан доверенным ключом ECDSA P-256.
Это самостоятельно сгенерированная пара ключей, а не сертификат: ни центра сертификации,
ни расходов здесь нет. Создайте её один раз и держите приватный ключ вне репозитория:

```powershell
$dir = "$env:LOCALAPPDATA\LocalAi\release-signing"
New-Item -ItemType Directory -Force -Path $dir | Out-Null
$ec = [System.Security.Cryptography.ECDsa]::Create(
    [System.Security.Cryptography.ECCurve]::CreateFromFriendlyName("nistP256"))
[IO.File]::WriteAllBytes("$dir\release-signing-private.pkcs8.der", $ec.ExportPkcs8PrivateKey())
[IO.File]::WriteAllBytes("$dir\release-signing-public.spki.der", $ec.ExportSubjectPublicKeyInfo())
$ec.Dispose()
icacls $dir /inheritance:r /grant:r "$($env:USERNAME):(OI)(CI)F"
```

Подписывайте пакет утилитой `localai-release-signer`. Она собирает манифест тем же
каноническим сериализатором, которым пользуется проверяющий, приводит подпись к
канонической форме low-S, обязательной для верификатора, и перепроверяет результат ещё до
публикации:

```powershell
localai-release-signer sign `
    --package publish\localai-package.zip `
    --package-uri https://github.com/<owner>/<repo>/releases/download/0.1.2/localai-package.zip `
    --release-version 0.1.2 `
    --version-directory d9c52d2 `
    --out publish\release
```

Проверка выполняется публичным ключом, встроенным в `LocalAi.Installer.Core`
(`ReleaseTrustAnchor`), а не файлом рядом с утилитой. Поэтому подпись ключом, которому
выпущенный установщик не доверяет, падает сразу, а не на машине пользователя. При провале
проверки на диск не пишется ничего. Публичную половину держите в репозитории по пути
`src/LocalAi.Installer.Core/Releases/release-signing-public.spki.der`, приватная не должна
попадать в репозиторий никогда.

Публикуйте `release-manifest.json` и `release-manifest.sig` ассетами релиза рядом с
пакетом. Правила полей, о которые проще всего споткнуться: `ReleaseVersion` — строгий
semver **без префикса `v`**, `PackageSha256` — hex **в верхнем регистре**, `PackageUri` —
только `https`, без userinfo и фрагмента.

Authenticode — отдельный и необязательный механизм: не указывайте
`--require-authenticode`, и установщик полностью пропустит проверку доверия к
исполняемым файлам. Подписанные бинарники нужны лишь для того, чтобы не появлялось
предупреждение SmartScreen на машинах, отличных от сборочной.

### Неизменяемые версии и атомарная активация

Опубликуйте CLI, MCP-серверы, брокер, контракты и их зависимости среды выполнения
в новый промежуточный каталог. Проверьте полный результат, затем один раз скопируйте
его в `bin\versions\<version>`. Каталог опубликованной версии неизменяем: активация
никогда не обновляет и не удаляет его, а исторические версии остаются доступными для
отката.

Отдельно опубликованный launcher установите по пути
`bin\launcher\localai-launcher.exe`. Codex, Claude, Git hooks и обёртки делегирования
должны регистрировать этот стабильный исполняемый файл вместе с префиксом инструмента,
например:

```text
localai-launcher.exe run codesearch-mcp
localai-launcher.exe run locallm-mcp
localai-launcher.exe run localai
```

Активная версия хранится в атомарно заменяемом документе `bin\current.json`:

```json
{"schemaVersion":1,"version":"<version>"}
```

После проверки каталога кандидата активируйте его:

```powershell
bin\launcher\localai-launcher.exe activate <version>
bin\launcher\localai-launcher.exe activate <version> --stop-running
```

Первая форма завершается ошибкой, пока версия используется процессом, запущенным через
launcher. Вторая останавливает только процессы, чей точный путь исполняемого файла или
свежая идентичность сборки брокера относится к предыдущей версии, а затем переключает
указатель. Она не останавливает Ollama или несвязанные процессы `dotnet`. Для отката
активируйте ранее проверенный неизменяемый каталог. Все запросы к моделям, включая
команды совместимости, по-прежнему проходят через общий FIFO-брокер; прямой доступ к
Ollama не поддерживается.

### Совместимость брокера и запуск

Схема 3 файла `host.json` брокера публикует явную версию протокола и стабильное семейство
совместимости сборки. Путь к его assembly остается диагностической записью и записью
launcher о владении версией; работоспособность клиента не зависит от совпадения путей DLL.
Поэтому совместимые установленные и разрабатываемые клиенты используют один
общесистемный брокер даже при разных путях DLL.

Свежий работающий несовместимый или устаревший host остается запущенным, но наблюдающий
клиент сразу получает `broker_incompatible` и не пытается запустить второй брокер. При
запуске ранний ненулевой код
завершения дочернего процесса дает `broker_start_failed`, а ограниченное ожидание без
наблюдения совместимого работоспособного состояния дает `broker_start_timeout` с
последним наблюдением. Дочерний процесс с нулевым кодом завершения, вероятно, проиграл
`broker.lock` другому процессу, поэтому клиент наблюдает состояние host владельца этой
блокировки только в тех же границах. CodeSearch сохраняет лексический fallback для
`broker_start_timeout`.

Эти правила не изменяют singleton FIFO, runtime ACL, активацию неизменяемых версий,
full-VRAM/zero-offload или запрет прямого доступа к Ollama.

## Модельно-ориентированное маршрутизирование

Встроенный каталог `model-routing.json` сопоставляет каждый локальный профиль задачи с одной или несколькими подходящими моделями. Профили охватывают обычный и технический перевод, а также перевод изображений; OCR и визуальный анализ; векторные эмбеддинги и детерминированный точный поиск; анализ, редактирование, ревью и переранжирование кода; анализ журналов; извлечение и классификацию; краткие сводки, синтез по нескольким файлам и планирование.

Брокер соблюдает эти инварианты:

- Уровни контекста диапазонируют от 2К до официального максимального для каждой модели (до 256К). Уровень может использоваться только тогда, когда предварительная проверка показывает, что полный раннер укладывается в VRAM.
- Холодная модель проходит предварительную проверку с пустым содержимым перед отправкой реальной задачи.
- `/api/ps` должен сообщать `size_vram == size`; отключение CPU или системной RAM вызывает именно эту комбинацию модели/контекста и запускает установленный резервный вариант.
- Планировщик предпочитает совместимую работу для резидентной модели, фиксирует каждый выбранный снимок, упорядочивает его задачи по прогнозируемой длительности, ждёт до двух секунд для сбора связанной работы перед переключением или длительной задачей и гарантирует включение задачи, ожидающей более 15 минут, в следующий совместимый снимок. Фактическая длительность успешного выполнения возвращается в безопасную скользящую оценку.
- Резидентные модели один раз выгружаются после 30 минут без queued или running работы. Заблокированный зависимостью шаг workflow всё ещё считается ожидающей работой.
- Перед холодным переключением модели брокер выгружает все другие раннеры из управляемого каталога. Неизвестные внешние процессы Ollama не затрагиваются.
- Эксперименты отслеживаются независимо для каждого профиля задачи и модели. Новый кандидат запускается для первых десяти завершённых логических задач каждого применимого профиля, затем эксперимент приостанавливается для проверки владельцем; до этого report gate обратная связь отклоняется. Единственное раннее исключение — `continue_experiment`, которым можно сбросить circuit breaker, открытый двумя последовательными техническими ошибками. Техническая, структурная или контекстная ошибка запускает established fallback. Фрагменты перевода используют один workflow ID и учитываются как одна попытка после итоговой проверки, сохраняя исходную категорию ошибки кандидата при broker fallback.
- Телеметрия экспериментов хранится в течение семи дней и содержит только идентификаторы рабочих процессов/задач/моделей, счетчики, результаты, временные метки и оценки использования токенов. Она сообщает о локальном вводе и выводе, общем объеме локальной обработки, избежании генерации в облаке и чистом уменьшении контекста в облаке отдельно. Запросы, ответы, содержимое файлов, байты изображений, пути и секретные данные исключены.

LocalLm предоставляет эти инструменты управления моделями и перевода MCP:

| Инструмент | Назначение |
|---|---|
| `translate_local` | Перевод текста, проверка защищенной структуры Markdown и добавление фактической атрибуции модели. |
| `local_models_status` | Показать установленные, резидентные, отсутствующие рекомендуемые и состояние эксперимента. |
| `local_model_preflight` | Загрузить одну модель с заданным контекстом без содержимого задачи и вернуть подтверждение полного размещения в VRAM. |
| `local_models_sync` | В очереди установка рекомендованных моделей из списка разрешенных. |
| `local_model_experiment_report` | Показывает попытки выполнения логических задач, ошибки, откаты, время выполнения, количество «холодных» и «тёплых» запусков, локальную обработку, избежание генерации в облаке и чистое уменьшение контекста. |
| `local_model_feedback` | Продвигать, продолжать, ограничивать до резервного или отключить одну пару задачи/модель. |

`translate_local` — валидируемый путь локального перевода. Вызывающий агент решает, выполнять перевод локально или в облаке; LocalAi не навязывает эту политику.

`read_image` принимает `VisualAnalysis`, `Ocr` или `ImageTranslation`; `ask_local`
принимает явный текстовый профиль задачи. Явная модель является переопределением, подлежащим тем же требованиям по функциональности, установке, контексту и проверке полной VRAM.

## Время выполнения и безопасность

- CodeSearch и LocalLm отправляют всю работу с моделями через устойчивый LocalAi FIFO брокер.
  Прямые конечные точки агента Ollama не поддерживаются.
- Неизменяемое базовое генерирование строится из локального `dev` при наличии, иначе из локального
  `main`. Выбранный основной реф остается стабильным в манифесте репозитория.
- Каждый рабочий каталог получает точный генерация/дерево/недостаточно чистый контент оверлей под
  `%LOCALAPPDATA%\LocalAi`, поэтому ветвь хранит только ее отличия от базы.
- CodeSearch канонизирует индексируемый текст до Windows CRLF в памяти для хеширования, обрезки,
  и вложения. Исходные файлы никогда не переписываются.
- Существующие вектора используются только тогда, когда модель, размерности, формат блока, формат индекса
  и контракт нормализации все совпадают.
- Семантический индекс всегда использует модель вложения, записанную в заголовок индекса.
  Точный лексический поиск остается детерминированным и никогда не вызывает модель чата.
- Общие хуки после фиксации, после слияния, после переписи и после перехода вызывают
  `localai sync`; установка всегда явная.
- Разрешенный командный файл `native` по-прежнему направляется через брокер.
- Проекты MCP зарезервируют стандартный вывод для сообщений протокола stdio.
- Сгенерированные индексы, журналы, файлы процессов, учетные данные и состояние выполнения остаются вне
  Git.
- `RuntimeAcl.Ensure` терпим к путям брокера, которые атомарно перемещаются во время обхода,
  при этом все еще распространяя сбои ACL для путей, которые продолжают существовать.

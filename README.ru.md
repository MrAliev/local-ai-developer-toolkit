# Local AI Developer Toolkit (русский перевод)

[English version](../en/README.md) *(примечание: оригинальный файл ссылается на README.ru.md, структура сохранения в русской версии)*

## Обзор

Local AI Developer Toolkit — это решение .NET для запуска инструментов разработки с использованием локальных моделей через единый надежный брокер, доступный во всей машине. Оно объединяет поиск семантического кода, учитывающий репозиторий; интеграции MCP; помощников задач для локальных моделей и синхронизацию индекса Git — всё это без необходимости изменять исходные проекты при простое открытии репозитория.

Имя решения на уровне источника, пространства имен, команды и директории выполнения остаются `LocalAi`, `CodeSearch` и `LocalLm`. Название репозитория описывает весь комплект инструментов, а не переименовывает эти стабильные контракты.

## Основные возможности

- Надёжный машинный FIFO-протокол является единственным поддерживаемым транспортом для Ollama; он обеспечивает последовательное выполнение нагрузок от Codex, Claude, CodeSearch и LocalLm одновременно на одной машине.
- Кодовый поиск (CodeSearch) сочетает векторную схожесть с прямым сопоставлением текста, обеспечивая семантический и лексический кодпоиск с учётом структуры репозитория.
- Неприменимые базовые поколения отражают выбранный основной ветовой линк (mainline), в то время как точные наложения для каждого дерева рабочей копии содержат различия между текущим состоянием и исходным кодом ветки или изменения не закоммиченного контента.
- CodeSearch и LocalLm предоставляют stdio MCP серверы для интеграции с совместимыми AI клиентами.
- Синхронизация репозиториев и общие Git hooks работают только при явной активации (opt-in).

## Как компоненты интегрируются друг с другом

```text
Codex / Claude / MCP клиенты
          |
          +--> CodeSearch MCP/CLI --> индекс репозитория + оверлей рабочего дерева
          |
          +--> LocalLm MCP --------> помощники локальных задач
                          |
                          v
                 FIFO брокер LocalAi
                          |
                          v
                        Ollama
```

Брокер владеет транспортными механизмами моделей и надёжностью очереди. CodeSearch отвечает за разбивку файлов (chunking), эмбеддинги, неизменяемые поколения индекса, оверлеи и гибридный поиск по запросу. LocalLm реализует помощники чата и задач для локальных моделей, а также оценивает количество токов. `LocalAi.Cli` отвечает за регистрацию репозиториев, синхронизацию, совместимый транспорт и установку опциональных hook'ов Git.

## Предварительные требования (Prerequisites)

- .NET 10 SDK
- Доступ к https://api.nuget.org/v3/index.json для чистого восстановления пакетов;
- Ollama и установленная совместимая модель необходимы только при запуске функций, опирающихся на локальные модели. Сборка проекта и unit-тесты не запускают Ollama автоматически.

Файл `NuGet.config` сознательно очищает наследуемые источники пакетов, чтобы нерелевантные приватные фидеры не становились зависимостями для сборки.

## Быстрый старт (Quick start)

Восстановите и проверьте решение:

```powershell
dotnet restore LocalAi.slnx
dotnet test LocalAi.slnx --configuration Release --no-restore
```

Проверочный запуск синхронизации репозитория без применения внешней настройки:

```powershell
dotnet run --project src/LocalAi.Cli -- bootstrap --dry-run
dotnet run --project src/LocalAi.Cli -- repo status
```

Синхронизируйте авторизованный репозиторий явно:

```powershell
dotnet run --project src/LocalAi.Cli -- sync --root C:\path\to\repository
```

Установите общие цепочные Git hooks только после утверждения внешнего изменения контента:

```powershell
dotnet run --project src/LocalAi.Cli -- hooks install --root C:\path\to\repository
```

## Сборка и тестирование (Build and test)

Из корня репозитория выполните следующие команды по очереди или через baseline проверку одного вызова:

```powershell
dotnet restore LocalAi.slnx
dotnet build LocalAi.slnx --configuration Release --no-restore
dotnet test LocalAi.slnx --configuration Release --no-build
```

Одна команда для базовой верификации (аналогично `./test` в других проектах):

```powershell
dotnet test LocalAi.slnx --configuration Release
```

## Публикация исполняемых файлов (Publishing executables)

Публикуйте только те проекты, которые нужны:

```powershell
dotnet publish src/CodeSearch.Cli/CodeSearch.Cli.csproj --configuration Release --output publish/CodeSearch.Cli
dotnet publish src/CodeSearch.Mcp/CodeSearch.Mcp.csproj --configuration Release --output publish/CodeSearch.Mcp
dotnet publish src/LocalLm.Mcp/LocalLm.Mcp.csproj --configuration Release --output publish/LocalLm.Mcp
dotnet publish src/LocalAi.Cli/LocalAi.Cli.csproj --configuration Release --output publish/LocalAi.Cli
```

Директория `publish/` игнорируется в системных задачах. Публикация не регистрирует исполняемые файлы с AI клиентом и не устанавливает Git hooks автоматически.

## Работа времени (Runtime) и безопасность

- CodeSearch и LocalLm отправляют все запросы к моделям через надёжный FIFO брокер `LocalAi`. Прямые вызовы Ollama интерфейсов от агентов клиентов недопустимы в текущей конфигурации системы.
- Базовое поколение строится локально из ветки `dev`, если она существует, иначе используется локальная ветка `main`. Выбранный реф основного линкинга остаётся стабильным в манифесте репозитория.
- Каждое рабочее дерево получает точное наложение (оверлей) с содержанием кода / деревьями изменений и «грязными» файлами под папкой `%LOCALAPPDATA%\LocalAi`, поэтому ветка хранит только свои различия относительно базы данных модели.
- CodeSearch канонизирует индексированный текст к форматированию CRLF Windows в памяти для хеширования, разбивки на chunks и эмбеддингов; исходные файлы никогда не переписываются напрямую файловой системой без контроля через API/CLI команды проекта.
- Существующие векторы повторно используются только если модель, количество размерностей (dimensions), формат чанков, индекс формата и контракт нормализации полностью совпадают. Общие Git hooks по завершении коммита (`post-commit`), слияния (`post-merge`), переписывания истории (`post-rewrite`) и перехода к новой ветке/файлу (`post-checkout`) вызывают команду `localai sync`; установка всегда явная (не авто).
- Разрешённая совместимая команда `native` всё равно маршрутизируется через брокер.
- Проекты MCP резервируют стандартный вывод для сообщений протокола stdio.
- Сгенерированные индексы, логи процессы файлы токены доступа и состояние выполнения хранятся вне Git (в локальных директориях пользователя). Функции `RuntimeAcl.Ensure` переносят ошибки ACL на пути, которые продолжают существовать при атомарном движении брокером файлов в процессе обхода дерева репозитория.

## Проекты решений (.NET Solutions projects)

| Project | Назначение (Purpose / Цель проекта) |
|---|---|
| `src/LocalAi.Contracts` | Контракт протокола для Broker, индекса и репозитория; определения классов обмена данными между процессами. |
| `src/LocalAi.Broker` | Надёжный машинный FIFO-протокол и эксклюзивный транспорт (Ollama). |
| `src/LocalAi.Broker.Client` | Клиентская интеграция с брокером процесса, подключение к stdio. |
| `src/LocalAi.Repository` | Идентификация репозитория, манифест, состояние рабочей копии дерева ветки (worktree state). |
| `src/LocalAi.Cli` | Среда командной строки: синхронизация репозиториев, транспорт совместимости и установка hooks Git. Также CLI утилиты для bootstrap/dry-run/status/sync/hook-install операций проекта решения `.NET`. |
| `src/CodeSearch.Core` | Модуль обработки текста (chunking), создание эмбеддингов, хранение индекса данных в базе векторов; оверлеи изменений и гибридный поиск. |
| `src/CodeSearch.Cli` | Команды для работы с индексом, статусом поиска, сканированием каталога файлов репозитория, запросам кода на основе лексических паттернов или векторных эмбеддингов через MCP интерфейсы. |
| `src/CodeSearch.Mcp` | Stdio-сервер MCP сервера для доступа к операциям CodeSearch из сторонних AI клиентов (Claude/Codex). |
| `src/LocalLm.Core` | Локальные помощники задач для генерации чатов; работа с метаданными изображений в контексте локальных LLM и оценка количества токенов запросов. |
| `src/LocalLm.Mcp` | Stdio-сервер MCP сервера, открывающий операции LocalLm (задачи) для интеграции сторонних AI клиентов. |
| `tests/*` | Юнит-тесты и интеграционные тестирование всех компонентов Toolkit; покрытия функциональности через автоматизацию CI/CD пайплайнов сборки проекта на основе .NET SDK. |

## Правила разработки (Development rules / Guidelines)

Не изменяйте существующие пространства имен, команды CLI, пути к runtime файлам репозитория и версии пакетов NuGet без явного утверждения обновления отдельным PR или веткой; используйте `git commit` только с обоснованием необходимости изменения. Маршрутизируйте работу Ollama исключительно через общий брокер (FIFO очередь). При реализации новых функционалов добавляйте точечные тесты к коду и выполняйте полную проверку решения перед публикацией бинарников проекта в репозитории NuGet или релизными каналами CI/CD. Сохраняйте актуальность README на английском языке (README.md) с русской версией (`README.ru.md`) синхронизированным; используйте одинаковые имена файлов, названия проектов и контракты API для поддержки мультиязычного проекта `.NET` решения в репозитории GitHub или GitLab. Сохраняйте UTF-8 без BOM (Byte Order Mark) и Windows CRLF (`\r\n`) разделение строк документации проекта локально на всех рабочих машинах разработчиков команды .NET/VSCode/GitHub Copilot/Claude Desktop/etc..

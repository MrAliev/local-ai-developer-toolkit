# Локальный инструментарий разработчика для искусственного интеллекта

[Русская версия](README.ru.md)

## Обзор

Локальный инструментарий разработчика для искусственного интеллекта — это решение .NET для запуска инструментов разработки локальных моделей через один устойчивый, машино-облачный брокер. Он объединяет репозитория с осознанным семантическим поиском кода, интеграции MCP, помощники задач для локальных моделей и синхронизацию индексов с учетом Git без изменения исходных проектов просто путем открытия репозитория.

Исходное решение на уровне кода, пространства имен, команд и каталога выполнения остаются названными `LocalAi`, `CodeSearch` и `LocalLm`. Название репозитория описывает полный инструментарий, а не переименовывает эти стабильные контракты.

## Основные возможности

- Устойчивый общесистемный FIFO-брокер — единственный поддерживаемый транспорт к Ollama; он последовательно выполняет общую очередь задач Codex, Claude, CodeSearch и LocalLm.
- Watchdog backend отделён от heartbeat аренды. У долгих задач нет общего ограничения по времени: после десяти минут без завершения broker проверяет доступность backend и residency модели и завершает попытку только после двух подряд подтверждённых отрицательных результатов. Timeout или неопределённый probe не прерывает здоровую многочасовую операцию.
- Синхронизация репозитория атомарно сохраняет безопасный progress snapshot. `index_status` показывает фазу, обработанные/всего/оставшиеся чанки, измеренную скорость и ETA во время сборки generation, не раскрывая тексты чанков или prompt jobs.
- Маршрутизация с учётом моделей выбирает подходящую модель по возможностям, текущей резидентности в VRAM, ограничению контекста, состоянию эксперимента и установленному порядку резервных вариантов.
- Снимки с осознанной моделью группируют работу для той же модели, выполняют более короткие совместимые задачи первыми и предотвращают истощение после 15 минут.
- CodeSearch сочетает сходство векторов с литеральным соответствием для репозитория с осознанным семантическим и лексическим поиском кода.
- Неизменные базовые генерации представляют выбранный локальный основной поток, тогда как точные перекрытия рабочего дерева содержат различия ветвей и измененного содержания.
- CodeSearch и LocalLm предоставляют серверы MCP через stdio для интеграции с совместимыми клиентами AI.
- Синхронизация репозиториев и общий Git hooks — явные операции опционального включения.
- Рекомендуемые модели обнаруживаются и устанавливаются через MCP без удаления существующих запасных моделей.

## Как компоненты работают вместе

```text
Codex / Claude / MCP clients
          |
          +--> CodeSearch MCP/CLI --> repository index + worktree overlay
          |
          +--> LocalLm MCP --------> local task helpers
                          |
                          v
                 LocalAi FIFO broker
                          |
                          v
                        Ollama
```

Брокер владеет моделью транспорта и долговечностью очереди. CodeSearch владеет чанкингом, эмбеддингами, генерацией неизменяемых индексов, оверлейсами и гибридным извлечением. LocalLm владеет локальными помощниками чата/задач и оценками токенов. `LocalAi.Cli` владеет регистрацией репозитория, синхронизацией, совместимым транспортом и установкой включаемых хуков.

### Работа с результатами CodeSearch

`search_code` использует модель эмбеддингов, записанную в индексе. Production-поиск
получает измеренный порог релевантности для этой точной модели и завершается закрытым
отказом `threshold not calibrated`, если профиля нет; порог другой модели никогда не
заимствуется.

Каждый результат поиска содержит непрозрачный `chunk_id`. Передайте его в
`get_code_chunk`, чтобы получить полный проиндексированный чанк исходника. ID привязан
к репозиторию, неизменяемой generation, текущему Git tree, хешу dirty-содержимого и
composite ordinal чанка. Malformed, cross-repository, stale или out-of-range ID
отклоняется, а не разрешается по другому snapshot.

Полученный из исходников MCP-вывод — это данные, а не инструкции. `search_code`
оставляет доверенную сводку индекса снаружи, а каждый результат возвращает в отдельном
блоке со свежим nonce:

```text
<untrusted-content id="<96-bit-lowercase-hex-nonce>" origin="search_code:<path>">
...полученный из исходника результат, включая chunk_id...
</untrusted-content id="<same-nonce>">
```

Успешный вывод `get_code_chunk` использует ту же границу. Ошибки валидации, status и
maintenance-вывод остаются снаружи. Потребители должны сохранять границу и не должны
исполнять или выполнять инструкции, найденные внутри неё.

Точная навигация C#, WPF/WinUI/MAUI/Avalonia XAML, TypeScript/JavaScript и Python хранится отдельно от векторов в
`semantic.sidx`. `localai sync` загружает основное решение через Roslyn/MSBuild, дополняет его
lossless-диапазонами XAML, platform namespaces, `x:DataType`, dependency/styled properties и
вариантами binding, а также импортирует ограниченный результат установленных индексаторов
`scip-typescript` и `scip-python`. Отсутствующий внешний индексатор отмечается как skipped в
manifest поколения и не ломает другие языки. Базовый SIDX атомарно публикуется вместе с CIDX,
а для dirty worktree строится компактный snapshot-bound semantic overlay с изменёнными
семантическими срезами и явными tombstone для удалённых документов. MCP предоставляет
`go_to_definition`, `find_references`, `find_implementations` и `find_relationships`; локальная
диагностика доступна командами:

```powershell
localai semantic status --root C:\path\to\repository
localai semantic definition --path src/App.cs --line 10 --column 15 --root C:\path\to\repository
localai semantic references --path src/App.cs --line 10 --column 15 --root C:\path\to\repository
localai semantic implementations --path src/IService.cs --line 4 --column 18 --root C:\path\to\repository
localai semantic relationships --path src/Service.cs --line 8 --column 20 --direction outgoing --kind implementation --root C:\path\to\repository
localai semantic config init
localai semantic config show
localai semantic lsp-config init
localai semantic lsp-config show
localai semantic fallback-config init
localai semantic fallback-config show
localai semantic evaluate --cases tests/CodeSearch.Tests/Fixtures/SemanticNavigation/cases.json --root C:\path\to\repository
```

Глобальный файл `%LOCALAPPDATA%\LocalAi\semantic-indexing.json` настраивает включение
адаптеров, пути и аргументы executables, выходные файлы, timeout, лимит вывода процессов и все
лимиты SCIP parser. Policy доверенного адаптера также явно задаёт legacy fallback позиций:
`Utf16` для `scip-typescript` и `Utf32` для `scip-python`; прямой импорт SCIP без такой policy
по-прежнему отклоняет неоднозначный индекс. Файл читается при каждом sync, поэтому изменение не
требует пересборки LocalAi. На Windows npm `.cmd` shims разрешаются через PATH/PATHEXT с
сохранением лимита вывода, timeout и завершения дерева процессов.

Live-навигация включается явно через `%LOCALAPPDATA%\LocalAi\language-servers.json`; изменение
этого файла не требует пересборки LocalAi. В нём настраиваются общий переключатель,
executable/arguments по языкам, таймауты запросов и shutdown, максимальный размер JSON-RPC и
ограниченный stderr. `localai semantic lsp-config init` создаёт отключённые по умолчанию шаблоны
для TypeScript/JavaScript, Python, HTML и C#. MCP-клиент передаёт версии через
`lsp_open_document` и закрывает документ через `lsp_close_document`; пока документ открыт,
точные ответы LSP для definition/reference/implementation имеют приоритет, после close используется snapshot-bound SIDX. При обрыве
transport сервер один раз перезапускается и получает все открытые документы с последними version
и полным text до повторения запроса. Repository-relative пути на всех ОС нормализуются через `/`;
нативные абсолютные пути существуют только на границе LSP `file://`.
Постоянные запросы implementations и relationships используют точный граф SIDX. Направление
incoming находит реализации, overrides и производные типы; outgoing возвращает соответствующие
базовые или интерфейсные символы. Для relationship-запросов эвристический текстовый поиск не
используется.

Если ни LSP, ни snapshot-bound SIDX не разрешили символ, LocalAi может выполнить ограниченный
syntax/text-поиск. Файл `%LOCALAPPDATA%\LocalAi\semantic-navigation.json` включает этот fallback
и задаёт лимиты числа файлов, размера файла, числа результатов, длины идентификатора и режим
регистра. Он читается при каждом запросе, поэтому изменение не требует пересборки. Результаты
fallback всегда имеют точность `Heuristic` и никогда не повышаются до precise.
Marker-based команда `semantic evaluate` выводит correctness, process-cold время загрузки,
перцентили первого/warm запроса, наблюдаемую разницу памяти и общий размер base/overlay SIDX.
Текущий baseline описан в
[semantic-navigation-evaluation.ru.md](docs/semantic-navigation-evaluation.ru.md).

Эквивалентные команды CLI:

```powershell
dotnet run --project src/CodeSearch.Cli -- search --query "where is the broker queue" --root C:\path\to\repository
dotnet run --project src/CodeSearch.Cli -- get-chunk --id "<chunk_id>" --root C:\path\to\repository
```

Измеренный откалиброванный профиль, происхождение корпуса, результаты A/B, эвристика
токенов и ограничения приведены в
[оценке retrieval CodeSearch](docs/codesearch-evaluation.ru.md).

## Предварительные требования

- .NET 10 SDK
- Доступ к `https://api.nuget.org/v3/index.json` для чистого восстановления


```powershell
C:\path\to\LocalAi\bin\launcher\localai-launcher.exe run localai hooks install --root C:\path\to\repository
```

## Что настраивает установщик

Законченная установка должна оставлять машину, которой действительно можно пользоваться,
поэтому мастер делает три вещи помимо копирования исполняемых файлов. Каждая показана на
странице подтверждения, и ни одна не применяется до того, как запуск подтверждён.

**Интеграция клиентов.** Для каждого обнаруженного AI-клиента мастер регистрирует MCP-серверы
`codesearch` и `locallm` на стабильный путь launcher и записывает управляемый блок инструкций в
глобальный файл инструкций этого клиента — `~/.claude/CLAUDE.md` для Claude, `~/.codex/AGENTS.md`
для Codex. Для обнаруженного клиента по умолчанию выбрано и то, и другое; ненайденный клиент
остаётся нетронутым, а явный выбор пользователя всегда важнее умолчания.

Блок намеренно не привязан к репозиториям. Индексация остаётся опциональной для каждого
репозитория, поэтому вместо предположений о том, что было настроено на машине сборки, блок
называет проверку (`localai repo status`) и две команды, подключающие любой репозиторий там,
где он склонирован. Без этого клиент на чистой машине умеет пользоваться локальными моделями,
но ни разу не предложит проиндексировать первый же открытый репозиторий.

Блок ограничен маркерами `<!-- BEGIN LOCALAI MANAGED INSTRUCTIONS -->` и парным ему конечным.
Всё между ними заменяется целиком при следующей установке, всё снаружи сохраняется, поэтому
обновление правил никогда не стоит пользователю его собственных заметок. Блок описывает
маршрутизацию — когда браться за `search_code` вместо текстового поиска, что относится к
`read_image`, `triage_log` и `ask_local` — и транспортные инварианты: только общий broker,
никогда Ollama напрямую, проверка полной резидентности в VRAM. Одних транспортных правил на
практике оказалось мало: они описывают, как вызов обязан идти, но не говорят, когда его вообще
делать, и агент, прочитавший только их, продолжает работать в облаке, пока установленные
инструменты простаивают.

**Модели.** Мастер устанавливает модели, которые машина способна удержать, и пропускает уже
установленные: список установленного спрашивается у broker, а не предполагается, и скачивается
только недостающее. Кандидаты берутся из подписанного манифеста релиза, а не из каталога
маршрутизации или реестра, потому что установщик моделей отвергает всё, что не может сверить с
подписью. Автоматический выбор берёт наибольший контекст, в который модель помещается; модель,
не влезающую в адаптер ни при каком контексте, он называет по имени, а не скачивает, чтобы
оставить непригодной. Скачанное проходит preflight, поэтому модель, не загрузившаяся целиком в
видеопамять, попадает в отчёт, а не принимается молча.

Раз выбор определяется манифестом, релиз, опубликованный без списка моделей, не установит ни
одной. Передавайте `--models` при подписании.

**Политика резидентности.** Страница видеопамяти пишет `%LOCALAPPDATA%\LocalAi\policy.json`.
Ослабление политики — сознательное действие, и оно остаётся видимым в отчёте о запуске.

### Подпись манифеста релиза

Установленной машине не нужен системный .NET. Все компоненты, включая брокер, поставляются
самодостаточными исполняемыми файлами, а брокер запускается как `LocalAi.Broker.exe` из
каталога того компонента, которому он понадобился. Путь берётся через
`AppContext.BaseDirectory`; **`Assembly.Location` использовать нельзя** — в single-file
публикации он возвращает пустую строку, и процесс умирает с «The path is empty», так и не
дойдя до брокера.

Установщик отвергает любой релиз, чей манифест не подписан доверенным ключом ECDSA P-256.
Это самостоятельно сгенерированная пара ключей, а не сертификат: ни центра сертификации,
ни расходов здесь нет. Создайте её один раз и держите приватный ключ вне репозитория:

```powershell
$dir = "$env:LOCALAPPDATA\LocalAi\release-signing"
New-Item -ItemType Directory -Force -Path $dir | Out-Null
$ec = [System.Security.Cryptography.ECDsa]::Create(
    [System.Security.Cryptography.ECCurve]::CreateFromFriendlyName("nistP256"))
[IO.File]::WriteAllBytes("$dir\release-signing-private.pkcs8.der", $ec.ExportPkcs8PrivateKey())
[IO.File]::WriteAllBytes("$dir\release-signing-public.spki.der", $ec.ExportSubjectPublicKeyInfo())
$ec.Dispose()
icacls $dir /inheritance:r /grant:r "$($env:USERNAME):(OI)(CI)F"
```

Сначала соберите пакет. Верификатор сверяет состав архива с
`LocalAiPackageLayout.PackageArtifactFiles` через `SetEquals`, поэтому в нём должно быть
ровно шесть артефактов плюс `localai-package.json` — плоско и без единой лишней записи.
**Именно поэтому исполняемые файлы обязаны публиковаться self-contained**: в формате нет
места для соседних сборок-зависимостей, и framework-dependent сборку выложить релизом
нельзя.

```powershell
localai-release-signer pack `
    --input publish\artifacts `
    --release-version 0.1.22 `
    --version-directory d9c52d2 `
    --out publish\release\localai-package.zip
```

Затем подпишите пакет утилитой `localai-release-signer`. Она собирает манифест тем же
каноническим сериализатором, которым пользуется проверяющий, приводит подпись к
канонической форме low-S, обязательной для верификатора, и перепроверяет результат ещё до
публикации:

```powershell
localai-release-signer sign `
    --package publish\release\localai-package.zip `
    --package-uri https://github.com/MrAliev/local-ai-developer-toolkit/releases/download/0.1.22/localai-package.zip `
    --release-version 0.1.22 `
    --version-directory d9c52d2 `
    --out publish\release
```

Перед публикацией прогоните готовые артефакты через собственный верификатор пакета из
установщика. Он выполняет тот же разбор архива, распаковку и сверку метаданных, что и
установка, поэтому структурная ошибка вылезет здесь, а не на чужой машине:

```powershell
localai-release-signer verify-package `
    --package publish\release\localai-package.zip `
    --manifest publish\release\release-manifest.json `
    --signature publish\release\release-manifest.sig
```

Проверка выполняется публичным ключом, встроенным в `LocalAi.Installer.Core`
(`ReleaseTrustAnchor`), а не файлом рядом с утилитой. Поэтому подпись ключом, которому
выпущенный установщик не доверяет, падает сразу, а не на машине пользователя. При провале
проверки на диск не пишется ничего. Публичную половину держите в репозитории по пути
`src/LocalAi.Installer.Core/Releases/release-signing-public.spki.der`, приватная не должна
попадать в репозиторий никогда.

Публикуйте `release-manifest.json` и `release-manifest.sig` ассетами релиза рядом с
пакетом. Правила полей, о которые проще всего споткнуться: `ReleaseVersion` — строгий
semver **без префикса `v`**, `PackageSha256` — hex **в верхнем регистре**, `PackageUri` —
только `https`, без userinfo и фрагмента.

Authenticode — отдельный и необязательный механизм: не указывайте
`--require-authenticode`, и установщик полностью пропустит проверку доверия к
исполняемым файлам. Подписанные бинарники нужны лишь для того, чтобы не появлялось
предупреждение SmartScreen на машинах, отличных от сборочной.

### Неизменяемые версии и атомарная активация

Опубликуйте CLI, MCP-серверы, брокер, контракты и их зависимости среды выполнения
в новый промежуточный каталог. Сливайте выход публикации всех проектов в этот один
каталог **вместе с подкаталогом `runtimes\`** — framework-dependent публикация без явного
RID кладёт windows-специфичные сборки вроде `System.Diagnostics.EventLog.dll` в
`runtimes\win\lib\net10.0\`, и `deps.json` разрешает их именно по этому пути. Плоское
копирование только верхнего уровня даёт каталог, который падает на старте с
`FileNotFoundException`.

Проверьте полноту результата до активации: в промежуточном каталоге должны быть все
исполняемые файлы компонентов (`codesearch.exe`, `codesearch-mcp.exe`, `locallm-mcp.exe`,
`localai.exe`, `localai-launcher.exe`, `LocalAi.Broker.exe`) и все зависимости
(`CodeSearch.Core.dll`, `LocalLm.Core.dll`, `LocalAi.Broker.Client.dll`,
`LocalAi.Repository.dll`, `ModelContextProtocol.dll`, набор `Microsoft.Extensions.*`).
Каталог из пары десятков файлов — это неполная публикация, а не релиз: запуск инструмента
из него падает с ошибкой загрузки `System.Runtime`, и приходит она от дочернего процесса,
а не от launcher.

Затем один раз скопируйте
его в `bin\versions\<version>`. Каталог опубликованной версии неизменяем: активация
никогда не обновляет и не удаляет его, а исторические версии остаются доступными для
отката.

Отдельно опубликованный launcher установите по пути
`bin\launcher\localai-launcher.exe`. Codex, Claude, Git hooks и обёртки делегирования
должны регистрировать этот стабильный исполняемый файл вместе с префиксом инструмента,
например:

```text
localai-launcher.exe run codesearch-mcp
localai-launcher.exe run locallm-mcp
localai-launcher.exe run localai
```

Активная версия хранится в атомарно заменяемом документе `bin\current.json`:

```json
{"schemaVersion":1,"version":"<version>"}
```

После проверки каталога кандидата активируйте его. Активация всегда требует явного
ожидания относительно заменяемого указателя, чтобы параллельная активация не была
затёрта молча:

```powershell
# Замена существующего указателя: укажите его текущий SHA-256.
$expected = (Get-FileHash bin\current.json -Algorithm SHA256).Hash
bin\launcher\localai-launcher.exe activate <version> --if-current-sha256 $expected

# Самая первая активация, когда bin\current.json ещё не существует.
bin\launcher\localai-launcher.exe activate <version> --if-current-missing

# Добавьте --stop-running, если предыдущая версия ещё используется.
bin\launcher\localai-launcher.exe activate <version> --if-current-sha256 $expected --stop-running
```

Вызов без обоих флагов — ошибка использования, код возврата 2. Активация также
завершается ошибкой, если наблюдаемый указатель не совпал с заявленным ожиданием. Без
`--stop-running` она завершается ошибкой, пока версия используется процессом, запущенным
через launcher; с этим флагом останавливаются только процессы, чей точный путь
исполняемого файла или свежая идентичность сборки брокера относится к предыдущей версии,
после чего указатель переключается. Она не останавливает Ollama или несвязанные процессы
`dotnet`. Для отката активируйте ранее проверенный неизменяемый каталог. Все запросы к моделям, включая
команды совместимости, по-прежнему проходят через общий FIFO-брокер; прямой доступ к
Ollama не поддерживается.

Остановка инструментов версии доступна отдельной командой:

```powershell
bin\launcher\localai-launcher.exe stop [--version <version>]
```

Брокера при этом просят завершиться, а не убивают. Рядом с `host.json` пишется запрос на
остановку с его PID и временем старта; брокер замечает его на том же heartbeat, который и так
публикует раз в секунду, перестаёт арендовать новые задачи, доводит текущую до конца и выходит
сам. Убивают только того, кто не ушёл до дедлайна: у брокера долговечная очередь, и он может
быть на середине инференса, поэтому уничтожение — последний ответ, а не механизм. Запрос
адресован не только по PID, но и по времени старта, чтобы устаревший не погасил здорового
брокера, унаследовавшего номер, и удаляется сразу после того, как принят.

У stdio-инструментов нет ни долговечного состояния, ни канала, чтобы их попросить, а клиент
поднимает их по требованию — для них жёсткое завершение единственный и достаточный способ.

Она останавливает процессы, работающие из активной версии — или из названной, — и указателя
не трогает. Активация останавливает их тоже, но только в рамках переключения, а шагом раньше
подменяется сам стабильный launcher. Перезаписать работающий exe Windows не даёт, и каждый
подключённый клиент держит по launcher-процессу на инструмент, поэтому установка могла
опубликовать новую версию, не суметь положить новый launcher и откатить всё целиком — при том
что лекарство лежало шагом дальше. Теперь установщик останавливает инструменты тогда и только
тогда, когда они мешают: обновление на простаивающей машине не трогает ничего.

Чтение указателя берёт **разделяемую** аренду, эксклюзивную — только сама подмена. Это важно:
каждый запущенный через launcher инструмент держит разделяемую аренду всё время жизни, поэтому
на машине, где LocalAi действительно используется, её всегда держит подключённый клиент, — и
установщик, бравший блокировку эксклюзивно просто ради чтения указателя, отказывал в
обновлении, не дойдя до активации, которая эти процессы и остановила бы. Чтению эксклюзивность
никогда не требовалась: подмену по-прежнему защищает `--if-current-sha256`, который ловит
изменившийся между чтением и активацией указатель, а не затирает его.

### Политика резидентности моделей

По умолчанию модель обязана **целиком помещаться в видеопамять**, всё остальное
отвергается. Это не настройка производительности. Модель, сползшая в системную память, не
падает — она просто становится в разы медленнее, и в ответе об этом ничего не сказано.

На машинах без пригодного дискретного адаптера политику можно ослабить:

```powershell
localai policy show
localai policy set --residency AllowPartialOffload
localai policy set --residency AllowCpu
localai policy set --idle-model-keep-alive-seconds 0
```

| Значение | Допускает | Отвергает |
| --- | --- | --- |
| `RequireFullVram` (по умолчанию) | полностью резидентную загрузку | всё остальное |
| `AllowPartialOffload` | часть модели на адаптере | чистую загрузку на CPU |
| `AllowCpu` | всё, что реально загрузилось | модель с нулевым размером |

Политика лежит в `%LOCALAPPDATA%\LocalAi\policy.json` и читается одинаково брокером, CLI и
установщиком. Отсутствующий, повреждённый или неизвестный по значению документ откатывается
к `RequireFullVram`: ошибка разбора не должна молча ослаблять проверку. Уже запущенный
брокер сохраняет прежнюю политику до перезапуска.

`IdleModelKeepAliveSeconds` задаёт, сколько секунд broker удерживает резидентную модель после
перехода в простой. Значение по умолчанию — `0`: модель выгружается сразу, если в очереди нет
работы, маршрутизированной на эту же модель. Задания для других моделей её не удерживают.
Задать другой интервал можно командой
`localai policy set --idle-model-keep-alive-seconds <секунды>`.

Деградация остаётся видимой: каждая загрузка ниже полной резидентности несёт предупреждение
с долей, которая дошла до видеопамяти, а `FullyResident` сообщает правду, а не константу.
Учтите, что блок инструкций для агентов по-прежнему требует full-VRAM валидации, поэтому
ослабление политики расходится с тем, что эти инструкции обещают.

NPU здесь не помогает. Всё идёт через Ollama, а её бэкенды — CPU, CUDA, ROCm, Metal и
Vulkan; NPU программируются отдельным стеком (OpenVINO, DirectML, Windows ML), и показатели
резидентности, на которых построена эта политика, к памяти NPU неприменимы.

### Совместимость брокера и запуск

Схема 3 файла `host.json` брокера публикует явную версию протокола и стабильное семейство
совместимости сборки. Путь к его assembly остается диагностической записью и записью
launcher о владении версией; работоспособность клиента не зависит от совпадения путей DLL.
Поэтому совместимые установленные и разрабатываемые клиенты используют один
общесистемный брокер даже при разных путях DLL.

Свежий работающий несовместимый или устаревший host остается запущенным, но наблюдающий
клиент сразу получает `broker_incompatible` и не пытается запустить второй брокер. При
запуске ранний ненулевой код
завершения дочернего процесса дает `broker_start_failed`, а ограниченное ожидание без
наблюдения совместимого работоспособного состояния дает `broker_start_timeout` с
последним наблюдением. Дочерний процесс с нулевым кодом завершения, вероятно, проиграл
`broker.lock` другому процессу, поэтому клиент наблюдает состояние host владельца этой
блокировки только в тех же границах. CodeSearch сохраняет лексический fallback для
`broker_start_timeout`.

Эти правила не изменяют singleton FIFO, runtime ACL, активацию неизменяемых версий,
full-VRAM/zero-offload или запрет прямого доступа к Ollama.

## Модельно-ориентированное маршрутизирование

Встроенный каталог `model-routing.json` сопоставляет каждый локальный профиль задачи с одной или несколькими подходящими моделями. Профили охватывают обычный и технический перевод, а также перевод изображений; OCR и визуальный анализ; векторные эмбеддинги и детерминированный точный поиск; анализ, редактирование, ревью и переранжирование кода; анализ журналов; извлечение и классификацию; краткие сводки, синтез по нескольким файлам и планирование.

Брокер соблюдает эти инварианты:

- Уровни контекста диапазонируют от 2К до официального максимального для каждой модели (до 256К). Уровень может использоваться только тогда, когда предварительная проверка показывает, что полный раннер укладывается в VRAM.
- Холодная модель проходит предварительную проверку с пустым содержимым перед отправкой реальной задачи.
- `/api/ps` должен сообщать `size_vram == size`; отключение CPU или системной RAM вызывает именно эту комбинацию модели/контекста и запускает установленный резервный вариант.
- Планировщик предпочитает совместимую работу для резидентной модели, фиксирует каждый выбранный снимок, упорядочивает его задачи по прогнозируемой длительности, ждёт до двух секунд для сбора связанной работы перед переключением или длительной задачей и гарантирует включение задачи, ожидающей более 15 минут, в следующий совместимый снимок. Фактическая длительность успешного выполнения возвращается в безопасную скользящую оценку.
- Резидентные модели выгружаются по истечении настраиваемого idle keep-alive (по умолчанию сразу), если в очереди нет работы для этой модели. Заблокированный зависимостью шаг workflow для резидентной модели всё ещё удерживает её; работа для другой модели — нет.
- Перед холодным переключением модели брокер выгружает все другие раннеры из управляемого каталога. Неизвестные внешние процессы Ollama не затрагиваются.
- Эксперименты отслеживаются независимо для каждого профиля задачи и модели. Новый кандидат запускается для первых десяти завершённых логических задач каждого применимого профиля, затем эксперимент приостанавливается для проверки владельцем; до этого report gate обратная связь отклоняется. Единственное раннее исключение — `continue_experiment`, которым можно сбросить circuit breaker, открытый двумя последовательными техническими ошибками. Техническая, структурная или контекстная ошибка запускает established fallback. Фрагменты перевода используют один workflow ID и учитываются как одна попытка после итоговой проверки, сохраняя исходную категорию ошибки кандидата при broker fallback.
- Телеметрия экспериментов хранится в течение семи дней и содержит только идентификаторы рабочих процессов/задач/моделей, счетчики, результаты, временные метки и оценки использования токенов. Она сообщает о локальном вводе и выводе, общем объеме локальной обработки, избежании генерации в облаке и чистом уменьшении контекста в облаке отдельно. Запросы, ответы, содержимое файлов, байты изображений, пути и секретные данные исключены.

LocalLm предоставляет эти инструменты управления моделями и перевода MCP:

| Инструмент | Назначение |
|---|---|
| `translate_local` | Перевод текста, проверка защищенной структуры Markdown и добавление фактической атрибуции модели. |
| `local_models_status` | Показать установленные, резидентные, отсутствующие рекомендуемые и состояние эксперимента. |
| `local_model_preflight` | Загрузить одну модель с заданным контекстом без содержимого задачи и вернуть подтверждение полного размещения в VRAM. |
| `local_models_sync` | В очереди установка рекомендованных моделей из списка разрешенных. |
| `local_model_experiment_report` | Показывает попытки выполнения логических задач, ошибки, откаты, время выполнения, количество «холодных» и «тёплых» запусков, локальную обработку, избежание генерации в облаке и чистое уменьшение контекста. |
| `local_model_feedback` | Продвигать, продолжать, ограничивать до резервного или отключить одну пару задачи/модель. |

`translate_local` — валидируемый путь локального перевода. Вызывающий агент решает, выполнять перевод локально или в облаке; LocalAi не навязывает эту политику.

`read_image` принимает `VisualAnalysis`, `Ocr` или `ImageTranslation`; `ask_local`
принимает явный текстовый профиль задачи. Явная модель является переопределением, подлежащим тем же требованиям по функциональности, установке, контексту и проверке полной VRAM.

Строка notice каждого инструмента сообщает экономию предложением, а не числом, которое надо
истолковать. Задача, слишком мелкая, чтобы что-то сэкономить, так и говорит: скриншот 336×52
стоит около двух десятков токенов при прямом просмотре, и любой полезный ответ о нём длиннее,
поэтому делегирование здесь — честная работа без экономии. Это подсказка о том, что стоит
делегировать, а не сломавшийся счётчик.

## Время выполнения и безопасность

- CodeSearch и LocalLm отправляют всю работу с моделями через устойчивый LocalAi FIFO брокер.
  Прямые конечные точки агента Ollama не поддерживаются.
- Неизменяемое базовое генерирование строится из локального `dev` при наличии, иначе из локального
  `main`. Выбранный основной реф остается стабильным в манифесте репозитория.
- Каждый рабочий каталог получает точный генерация/дерево/недостаточно чистый контент оверлей под
  `%LOCALAPPDATA%\LocalAi`, поэтому ветвь хранит только ее отличия от базы.
- CodeSearch канонизирует индексируемый текст до Windows CRLF в памяти для хеширования, обрезки,
  и вложения. Исходные файлы никогда не переписываются.
- Существующие вектора используются только тогда, когда модель, размерности, формат блока, формат индекса
  и контракт нормализации все совпадают.
- Семантический индекс всегда использует модель вложения, записанную в заголовок индекса.
  Точный лексический поиск остается детерминированным и никогда не вызывает модель чата.
- Общие хуки после фиксации, после слияния, после переписи и после перехода вызывают
  `localai sync`; установка всегда явная.
- Разрешенный командный файл `native` по-прежнему направляется через брокер.
- Проекты MCP зарезервируют стандартный вывод для сообщений протокола stdio.
- Сгенерированные индексы, журналы, файлы процессов, учетные данные и состояние выполнения остаются вне
  Git.
- `RuntimeAcl.Ensure` терпим к путям брокера, которые атомарно перемещаются во время обхода,
  при этом все еще распространяя сбои ACL для путей, которые продолжают существовать.

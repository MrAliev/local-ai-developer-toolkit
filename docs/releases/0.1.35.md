# LocalAi 0.1.35

[Русская версия](0.1.35.ru.md)

One fix, found by hitting it rather than by reading for it.

## The broker no longer pins whoever started it

A git worktree was removed. `git worktree remove` deregistered it and the files stayed on disk.
Deleting them failed from bash, from PowerShell and from Explorer, each reporting that another
process was using the directory and naming no process. Killing the LocalAi broker released it
instantly.

The broker is started on demand by the first client that needs it and then outlives that client by
hours. Its `ProcessStartInfo` named no working directory, so it inherited the caller's — and a
process holds its working directory open for as long as it runs. Whichever directory a client
happened to be sitting in when the broker first started became undeletable for the broker's entire
lifetime.

Nothing about this was specific to worktrees. Any directory that first started the broker was
pinned the same way, and the symptom never pointed at the broker: an operation on a repository
failed, and the process responsible was an unrelated background service started hours earlier from
a directory nobody was thinking about.

The broker now runs in its own runtime root, which is where it writes anyway. The directory is
created before the start, so a first-ever start does not fail on a path that does not exist yet.

## Upgrading

The fix applies to brokers started by 0.1.35 onward. A broker already running from an earlier
version keeps holding whatever directory it inherited until it is next restarted — installing this
version restarts it.

## Verification

An empty `WorkingDirectory` is exactly what inheritance looks like, so the test asserts the value
rather than the absence of a symptom, and it was checked the way a test should be: with the
assignment removed it fails, and it passes again once restored.

The start delegate keeps its shape, so the several hundred tests built on it are untouched.

Full suite across all nine projects: **1679 passed, 4 skipped, 0 failed**.

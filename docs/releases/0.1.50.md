# LocalAi 0.1.50

[Русская версия](0.1.50.ru.md)

This release carries the results of a full external code review: twenty-five findings —
one critical, sixteen major, seven minor, plus two accepted risks now partly retired —
every one closed with a fix and a test that pins the exact defect. Most of it is
structural: races that needed two processes and bad timing, parsers that trusted what
input said about itself, error text that pointed away from the cause. A machine that
never hit those windows behaves as before, only with the windows gone.

**This release does not rebuild anything.** Chunk boundaries, the semantic format and the
generation identity are unchanged; an existing index stays valid.

## Two syncs of one repository can no longer trample each other

Synchronization now runs under a named per-repository gate. The second `localai sync` —
another client, a Git hook, a second window — waits briefly and then exits with its own
named outcome, "repository busy", before touching any shared state: no progress record,
no manifest write, no `Failed` stamped over the other run's story. The base-generation
pointer advances by compare-and-swap, so two finishing syncs cannot silently overwrite
each other, and an overlay that drifted while it was being built — a commit or an edit
landing mid-embedding — is discarded and rebuilt rather than saved wrong. Search performs
the matching check on the read side: a snippet whose file changed after the snapshot was
taken is refused with `snapshot_changed` instead of quoting lines that no longer exist.

## The broker stops believing what inputs say about themselves

The durable index loader validates every length, count, offset and enum it reads before
allocating anything, so a truncated or corrupt `.cidx` file fails as one message — the
index is corrupt, rebuild with `localai sync` — instead of an out-of-memory or a random
runtime exception. Embedding vectors are checked for finiteness both where doubles become
floats and inside normalization, which refuses zero and non-finite magnitudes rather than
letting a NaN into the durable index to destabilize every ranking comparison it touches.
Ollama success responses now have a size ceiling with an early refusal for declared
oversized bodies, closing the one path where a misbehaving endpoint could feed the shared
queue an unbounded response. Quarantined job records — previously the one artifact no
retention bound covered — age out by time, count and total size, with a grace period that
guarantees a fresh record survives long enough to be inspected. A failure to write the
telemetry ledger no longer takes the job's result down with it, and the runtime ACL sweep
refuses every reparse point instead of following it.

## The installer treats your configuration as yours

Applying agent configuration is now a true compare-and-swap: a Codex or Claude config
save landing between the installer's check and its write is detected, the displaced
content is restored, and the apply refuses — and the backup file always holds what was
actually displaced. Rollback restores only files that still hold what the apply wrote;
somebody else's later edit is left as found and named. Strict TOML validation applies
only to the managed sections the installer actually rewrites: a float, a datetime, an
inline table or a multiline array elsewhere in `config.toml` no longer refuses the whole
install, while TOML multiline strings stay refused everywhere because their bodies can
spoof a section header for a line-oriented editor. A config that is not valid UTF-8 is
refused before any plan exists instead of being silently re-encoded with replacement
characters. An unexpected error in the wizard now lands in a visible error banner instead
of killing the process, and Codex tool approvals follow a per-tool matrix on upgrade:
only the literal `approve` an earlier installer wrote is rebuilt, `deny` and any
stricter-than-matrix choice are yours and survive.

## Local model answers are data, exactly like search hits

Everything a local model derived from content — `ask_local`, `triage_log`, `read_image`,
`translate_local` — now arrives inside the same nonce-bound `<untrusted-content>` boundary
CodeSearch uses, with the notice line outside as the process's own words: a comment in a
file can say "ignore previous instructions", and a small model can repeat it. The inputs
themselves are bounded — at most 64 files sharing a ~720K-character budget with a visible
`TRUNCATED` marker, at most 8 images within 60 MB and 80 megapixels — so one oversized
call cannot occupy the shared queue for everyone. A host cancelling an MCP call gets a
cancellation back, not a "model failed" sentence inviting a retry nobody is waiting for.

## Verifying the download

Publishing a release now records the digest of every asset in GitHub's attestation log,
which the release page cannot rewrite. With the GitHub CLI installed:

```powershell
gh attestation verify LocalAi.Installer.exe --repo MrAliev/local-ai-developer-toolkit
```

A swapped or corrupted download fails this check even if the SHA-256 published beside it
was swapped to match. On the signing side, the release key's working copy is now
DPAPI-wrapped and bound to the signing account and machine, and the signer refuses to
touch it while the key directory's ACL grants access to anyone beyond SYSTEM,
Administrators and that account. The Authenticode signature itself remains the open half
of the hardening issue, so SmartScreen still shows its prompt — the check above is the
stronger answer in the meantime.

# LocalAi 0.1.34

[English version](0.1.34.md)

Функция, которая не могла работать, тест, который не мог упасть, и разбор, нашедший обоих.

## Языковому серверу можно сказать, как запускаться

`typescript-language-server` ищет tsserver в самом workspace. Если своего TypeScript там нет,
сервер отвечает `Could not find a valid TypeScript installation` и завершается. Поэтому
live-навигация по TypeScript была недоступна в любом репозитории без локального
`node_modules/typescript`, и настройками это не лечилось.

TypeScript 7 не закрывает разрыв, а расширяет его: он вообще перестал поставлять
`lib/tsserver.js`, так что на машине с совершенно свежим глобальным TypeScript этому серверу всё
равно нечего запускать.

Сказать, где лежит рабочий tsserver, можно членом LSP `initializationOptions` — и клиент его
никогда не отправлял: этого слова не было во всём дереве исходников, а в политике не было места,
куда его положить. Теперь есть и то, и другое, и `language-servers.json` принимает его для каждого
языка:

```json
"typescript": {
  "Enabled": true,
  "Executable": "typescript-language-server",
  "Arguments": ["--stdio"],
  "InitializationOptions": { "tsserver": { "path": "…/node_modules/typescript/lib/tsserver.js" } }
}
```

Две детали здесь несущие. Член **отсутствует, а не равен null**, когда ничего не настроено:
сервер, читающий его без проверки, получит null там, где ждёт объект. И поле сделано
необязательным, а не бампом `SchemaVersion`, — установка, настроенная до 0.1.34, продолжает
читаться; бамп обесценил бы каждый существующий файл и молча подставил бы выключенные умолчания.

Путь не угадывается никогда. LocalAi не станет искать tsserver за оператора: навигация по чужому
TypeScript даёт неправильные ответы, выглядящие правильными.

## Фикстура, сообщавшая о дефекте, который сама и создавала

Реальная фикстура TypeScript проверяла только наличие бинарника сервера, а workspace строила во
временном каталоге, где TypeScript нет. На машине с установленным сервером она запускалась, падала
на initialize и сообщала о дефекте продукта, который на деле был отсутствующим prerequisite. На
машине без сервера — пропускалась. Ни один из исходов не говорил, что live-навигация по TypeScript
не проверялась ни разу.

Теперь фикстура находит пригодный tsserver и называет его явно. Skip-guard намеренно узкий:
срабатывает только при доказанно отсутствующем prerequisite. Присутствующий сервер плюс
присутствующий tsserver, упавший на initialize, оставляет тест красным. Превращать неудачный
initialize в пропуск — это форма дефектов 0.1.31 и 0.1.32, где opt-in фикстуры, не работавшие ни
разу, читались как покрытие.

Обе реальные LSP-фикстуры, TypeScript и pyright, теперь выполняются.

## Тест, который не мог упасть

`InvalidOrUnknownConfigurationFallsBackToDisabledDefaults` писал документ в camelCase. Стор
language-server не задаёт naming policy, поэтому его члены именуются так же, как в CLR, — и ни один
член того документа не связывался. Тест проходил потому, что не связывалось вообще ничего: он
прошёл бы и с удалённой защитой от неизвестных членов. Это хуже, чем отсутствие теста, — покрытие
его считало.

Теперь он строится из реальной сериализованной политики, и проверен так, как прежний не проверялся
никогда: при ослаблении `UnmappedMemberHandling` до `Skip` тест падает и снова проходит после
возврата защиты. Прежнее имя обещало две проверки и не делало ни одной — поэтому тестов стало два.

## Одно определение runtime root

Пять мест собирали `%LOCALAPPDATA%\LocalAi` из одних и тех же двух частей: CLI трижды, клиент
broker в качестве fallback и process controller launcher'а. Каждое было верным — и каждое было
отдельным ответом на вопрос «какая установка», тем самым, ради единственного ответа на который в
0.1.33 и делался внедряемый runtime root. Теперь все они ссылаются на одно определение. Путь не
изменился, так что это убирает возможность расхождения, а не случившееся расхождение.

## Проверка

Полный прогон по девяти проектам — **1678 passed, 4 skipped, 0 failed**, против 1665 passed и
одного падавшего в 0.1.33.

Оставшиеся четыре пропуска — тесты симлинков и reparse-точек, которым нужен Windows Developer Mode.
Они защищают от чтения за пределами репозитория по ссылке и пропускаются из-за доказанно
отсутствующей возможности, а не из-за отказа, — но прогнать их на машине, где эта возможность есть,
стоит.

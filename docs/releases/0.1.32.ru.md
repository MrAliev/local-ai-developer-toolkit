# LocalAi 0.1.32

[English version](0.1.32.md)

Один дефект — и причина, по которой его не видели.

## Единый способ находить исполняемые файлы

npm ставит для команды на Windows два файла: POSIX-скрипт без расширения и `.cmd`-шим.
`File.Exists` для первого истинно, и он не является исполняемым файлом Win32.

`ScipAdapterRunner` исправили для этого в 0.1.24–0.1.27: он следует порядку PATHEXT и сообщает
«не найдено», если шима нет. `StdioLanguageServerClient` держал собственную копию резолвера,
которая проверяла голый файл первым, — поэтому live-навигация на Windows возвращала незапускаемый
скрипт для любого языкового сервера, установленного через npm, а это оба, для которых она
поставляет умолчания.

Незамеченным это осталось потому, что live-навигация включается явно, а её фикстуры пропускались
без установленных серверов: та же форма, что у отказа scip-python в 0.1.31, из-за которого ни один
Python-репозиторий не мог опубликовать индекс.

Теперь один `ExecutableResolver` с правильным поведением, используемый обоими. `Find` сообщает
null, когда команду нельзя запустить, — это не то же самое, что отсутствие файла.

## Фикстуры находят инструменты так же, как продукт

Фикстуры SCIP и LSP требовали переменную окружения с путём к исполняемому файлу. `scip-typescript`
был установлен на машине, где это нашлось, и его фикстура пропускалась при каждом прогоне —
покрытие, которое существует и не выполняется. Теперь обнаружение идёт через тот же резолвер.

С установленными языковыми серверами пути TypeScript SCIP, Python SCIP и pyright прогоняются
впервые.

## Тесты в проекте интеграционных тестов установщика

Проект был в решении, требовался `SolutionShapeTests` и не содержал тестов. Теперь шесть проходят
по реальным моделям мастера, ничего не устанавливая, и держат инварианты, верные на любой машине:
шаг вперёд ровно на одну позицию с согласованным отчётом, возврат к первому шагу, запуск
предлагается только на странице подтверждения, неразрешённый пакет сообщает об этом и не блокирует
остальные шаги.

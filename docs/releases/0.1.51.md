# LocalAi 0.1.51

[Русская версия](0.1.51.ru.md)

Two things this release adds are the two halves of a product's life it did not have: a way
out, and a way to know a newer version exists. Neither happens without being asked. The
uninstaller is a mode of the installer you already have, registered where Windows lists
programs; the update check is off until you switch it on, and even then it only tells you.

**This release does not rebuild anything.** Chunk boundaries, the semantic format and the
generation identity are unchanged; an existing index stays valid.

## A way out, registered in Apps & features

Until now removal was a checklist in the documentation. It is now one action, and it is where
people look for it: an installation registers itself in **Apps & features**, and that entry
runs a copy of the installer parked inside the runtime root — so removal is still reachable
long after the file you downloaded is gone.

What it removes is a matrix, not one hammer. Three presets — **full uninstall**, **disconnect
clients**, **reinstall-friendly** — over rows you can change one at a time, and every removal
is listed on a review page before anything happens: the runtime root, the MCP registrations in
each client's configuration, the managed instruction block between its markers, and the Git
hook dispatchers of each connected repository, listed from the runtime's own manifests. Your
own text and anybody else's registrations are untouched.

Three refusals are deliberate. The release signing key directory stays unless you confirm it
separately, because removing it makes an offline backup the only copy that exists. The broker
is asked to finish before the root is touched, and a run that cannot stop it removes nothing at
all rather than deleting files underneath a working process. And prerequisites installed
through winget, plus models pulled into Ollama, are shared with other software: the final page
names the `winget uninstall` and `ollama rm` commands instead of running them.

"Reinstall-friendly" is the row worth knowing about: the binaries go, the repository indexes
and the hand-tuned settings stay, so coming back costs an install rather than an afternoon of
re-embedding.

## The installer now asks what you came to do

Starting it no longer assumes an installation. It looks at the machine first and offers
install, update or repair, clean reinstall, or removal — and for anything it cannot do, it says
why: *"LocalAi 0.1.50 is already installed — use Update or repair."* An installation directory
that is there but not working keeps both ways out open, repair and removal, with the reason it
could not be read on the page.

## Knowing a release exists, and taking it

Nothing on a machine ever said "a newer release exists". Checking is opt-in, off until you tick
the box on the installer's review page or run:

```powershell
localai policy set --update-check on
```

What that permits is one request per interval — a day by default, with a per-machine offset so
a fleet installed from one image does not arrive in a spike — for the latest release manifest
and its signature. Nothing about the machine is sent: no identifier, no account, no usage. The
version inside the manifest is believed only after its signature verifies against the key this
build carries, so whoever answers the request cannot invent one. Every failure — no network, a
proxy rewriting the body, a signature that does not verify — records the same thing: no update
information, never a banner urging action.

The check runs on the broker's own loop, never on the job path, so no queued work ever waits on
GitHub. What it learns goes into a small state file, and every surface answers from that file
rather than the network: `localai doctor` prints an `update` line, and `index_status` carries
one trailing line when a newer verified release exists — and only then.

Applying stays an explicit act:

```powershell
localai update            # refuses while the broker has queued jobs
localai update --wait     # waits for them to finish first
```

It installs the newest signed release over the current one through the same machinery an
installation uses — verified manifest, verified package, immutable version directory, atomic
pointer swap — and touches nothing else. Prerequisites, models and client integrations stay as
they are.

## The two LSP tools stopped being the exception

Every tool in the `codesearch` server resolves an omitted repository root to the repository
containing the working directory. `lsp_open_document` and `lsp_close_document` required it, so
a caller who left it out exactly as they may everywhere else got the MCP layer's bare *"An
error occurred invoking 'lsp_open_document'"* with nothing naming the missing parameter. Both
now take the same optional root, and a test fails the build if any future tool declares a
required one. Two neighbouring gaps closed with it: `find_relationships` documented none of its
parameters, and `get_code_chunk` never said its root could be omitted.

## Documentation is now held to the same standard as code

A verification pass before this release found the signing runbook telling anyone planning a key
rotation that no background updater verifies against the trust anchor — three days after one
started doing exactly that. That sentence, and four more places describing where the key lives,
are corrected.

To stop the next one, CI now refuses a pull request that changes `src/` and no documentation,
unless its body says why none was needed. The rule cannot judge prose; what it refuses is
silence, which is the failure that actually happened.

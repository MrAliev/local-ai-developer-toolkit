# LocalAi 0.1.45

[Русская версия](0.1.45.ru.md)

Four defects, found by asking one question of the previous release: could its installer be
handed to somebody who has never had LocalAi on their machine? Each of them is invisible on a
computer that already has it installed, and each one costs a first-time installation.

**This release does not rebuild anything.** Chunk boundaries, the semantic format and the
generation identity are unchanged since 0.1.43, so an index built by 0.1.43 or 0.1.44 stays
valid and no sync is required beyond the ordinary one after a commit.

## Every release since 0.1.29 was signed with a model list of zero models

The installer accepts only models it can tie back to the signed manifest — the routing
catalogue and the public registry are what a human is shown, and neither is signed. `--models`
was optional when signing, and the publish script never passed it. Sixteen releases went out
with `"Models":[]`.

What that produced is worth stating plainly, because it looks like success. The models page
offers six models and reports which of them fit the adapter. The confirmation page lists them.
The run then plans zero installs, prints one line saying the manifest lists no models, and
finishes as **Installation complete**. The first real sign of trouble arrives days later, when
CodeSearch has no embedding model to index with.

The list is now built per release from the routing catalogue, with each model's download size
read from the model registry at signing time:

```
localai-release-signer models --out publish\release\release-models.json
```

Sizes are read rather than stored, because a tag republished with different quantisation keeps
its name: a number committed to the source tree goes stale silently and the installer starts
weighing the wrong one against somebody's video memory. A tag whose size cannot be read stops
the release instead of being skipped.

Three separate refusals now stand between that defect and a published release. `sign` will not
run without `--models` unless `--no-models` says the omission is deliberate; `release --publish`
refuses a manifest that carries no models; and the wizard reports a run that installed no model
as a failure, naming the reason and what to do about it, rather than as a line in the log under
a green heading.

## A failed first run left the machine unable to install at all

The video-memory page writes `policy.json` into `%LOCALAPPDATA%\LocalAi`, and that write creates
the directory with a plain `CreateDirectory` — inheriting whatever the parent grants. The
installation layout lease requires that root to carry a protected ACL, and is deliberately
forbidden from repairing one, so a root created that way is refused for good:

```
The LocalAi installation layout is unsafe (check: ValidateAcl): the directory still inherits
access rules.
```

Ordering the policy write after the package install was believed to close this, and it does —
while the package installs. A first run that fails before that point still reached the write:
no GitHub sign-in, no network, a cancelled download. The machine was then in a state where
every later attempt refused itself, with a message that names the condition and not the cure.

The policy is now stored only when there is an installation to store it into. A machine with
LocalAi installed can still change its residency without reinstalling; a machine without it is
left exactly as it was found, and the next run asks for the setting again.

For machines already in that state, the refusal now carries advice: it names the directory, and
says whether it holds installed versions. A root left behind by a failed run holds none and can
simply be deleted. A root with versions in it also holds this machine's repository indexes, so
that advice is never given for one — rebuilding those costs hours of a graphics card.

## A signed-out GitHub CLI passed every check and then failed the install

The release repository is private, and the installer reads it through the sign-in already
established with `gh auth login` rather than handling a token itself. The system check reported
whether the CLI existed. Whether it was signed in — the fact that actually decides whether this
machine can read a release — was discovered by trying, two pages later, as *could not determine
the newest release*: a sentence that describes a signed-out CLI exactly as it describes a
deleted tag or a dropped network.

The sign-in is now probed separately and reported on its own line, with the command to fix it.
It carries its own, longer timeout, because that probe contacts GitHub — and a probe that times
out is reported as unknown rather than as signed out, since telling someone to run a command
they have already run is worse than admitting the check did not finish. The same fact now
appears as a warning on the package page, as a clause on the confirmation page, and in the run
report.

The confirmation page also states plainly what an unverified release means: not only that
LocalAi will not be installed, but that the client applications will be left unconfigured,
because a registration written for a launcher that is not there is worse than none.

## Node 20 is a floor, not an exact version

Requiring exactly 20 told every machine running something newer that it had no Node at all, and
then offered to install a second runtime beside the one in use — after which PATH order decides
which of the two answers, and the check keeps failing.

Underneath it was a parser that did not know its own input. `node --version` prints `v20.20.2`,
and with no word boundary before the digits the match began after the first dot: the version
read as `20.2`, which happens to be right, while `v24.4.1` read as `4.1` and would have been
rejected. Nothing caught it because the only test that fed this a v-prefixed version expected a
rejection and got one, for the wrong reason.

## Upgrading

Install with the GUI installer from this release. Nothing else is required: no rebuild, no
re-sync, no change to any index on disk.

If you installed a previous release and it set up no models — which is every release since
0.1.29 — this one installs them. What is already present is left alone: the broker is asked
what the machine has and only the missing models are pulled.

If a previous attempt left `%LOCALAPPDATA%\LocalAi` behind without installing anything, and
installations now refuse themselves over inherited access rules, delete that directory and run
this installer again. It holds no installation to lose in that state, and this release no longer
creates it.

## Verification

The whole solution ran 1861 tests: 1857 passed and four were skipped for platform reasons.

Each of the four defects is now covered by a test that fails without its fix. The residency
writer is checked for not creating the root it used to create; the release model list is checked
against the manifest validator that the installer verifies with, and for refusing a model whose
size could not be read; the sign-in probe is checked for reporting signed-in, signed-out and
unfinished as three different answers; and Node is checked at 20, 22, 24 and 26 with the `v`
prefix the runtime actually prints, plus a rejection at 18.

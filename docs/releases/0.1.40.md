# LocalAi 0.1.40

[Русская версия](0.1.40.ru.md)

The Git hooks now install where Git will actually run them. On any repository that sets
`core.hooksPath` — which is most front-end ones — they were being written to a directory Git
never reads, and the index quietly stopped following HEAD.

## Hooks installed into a directory Git ignores

`localai hooks install` wrote its dispatchers into `$GIT_DIR/hooks` and reported success. A
repository that sets `core.hooksPath` makes Git ignore that directory completely, and husky,
lefthook and simple-git-hooks all set it — husky does so from `npm install`, through the
`prepare` script, without anybody deciding to. The install then succeeded, the hooks never ran
again, and nothing said so: the only symptom was `index_status` eventually reporting drift, to
whoever thought to look.

The resolver now follows `core.hooksPath`, relative paths included, resolving them against the
top of the working tree the way Git does, and against the common directory for a bare repository
that has none.

husky needs one thing more, and it is the reason this is not a one-line change. It points
`core.hooksPath` at `.husky/_`, a directory it deletes and regenerates on every run, so a
dispatcher written there would disappear at the next `npm install`. Its generated shims run
`.husky/<hook>` — for every standard hook, whether or not that file exists — so that is where
ours belongs. The directory is recognised by the `h` or `husky.sh` runner inside it rather than
by its name, so an ordinary directory called `_` is left alone.

Dispatchers that land in the working tree are added to `.git/info/exclude` rather than showing
up as untracked files in a repository whose `.gitignore` belongs to someone else. That file is
per-clone and tracked by nothing, which is what makes it the right place for a decision the tool
made rather than the project.

**If you installed hooks into a repository that uses husky before this version, re-run
`localai hooks install` once.** The old dispatchers in `$GIT_DIR/hooks` are inert but harmless,
and they resume working if the repository ever stops setting `core.hooksPath`.

## What SCIP actually gives us for symbol-level chunking

Issue #82 — chunking TypeScript and Python by symbol instead of by a 60-line window — rests on
the external indexers reporting the span of a definition's body. Nothing had established that
they do. This release carries the fixtures that answer it, under
`tests/CodeSearch.Tests/Fixtures/SymbolChunking`, together with a dependency-free reader that
measures the answer from a real index rather than from the SCIP schema.

Both adapters emit `enclosing_range`. Over definitions that have a body, `scip-python` 0.6.6
carries it for all of them, nested functions and decorated definitions included.
`scip-typescript` 0.4.0 carries it for every definition it gives a global symbol, and for
neither of the two kinds it does not: definitions declared inside a function body, and
declarations whose initialiser is a call — which is what `export const X = memo(() => …)` is.
Measured against a 2,653-file React repository, that is 2,991 body spans covering 67% of the
non-blank lines, with 955 files containing no definition body at all.

Nothing about chunking changes in this release. The finding is recorded because it narrows what
#82 can promise, and the fixtures are committed so that an adapter upgrade changing the answer
shows up as a failing measurement rather than as silently different chunk boundaries.

## Upgrading

Install with the GUI installer from this release. It stops the broker and the running MCP
servers itself, replaces them, and activates the new version. Re-run `localai hooks install` for
any repository whose hooks were installed before this version and that sets `core.hooksPath`;
repositories without it are unaffected and need nothing.

## Verification

The complete solution passed 1,784 tests with four platform-dependent skips, including five new
cases covering hook resolution: `core.hooksPath` is honoured, husky's regenerated runner directory redirects to its
parent, an ordinary `_` directory does not, working-tree dispatchers are excluded exactly once
across repeated installs, and hooks inside the Git directory are left out of that.

The process-runner tests no longer launch PowerShell to do it. They start a purpose-built child
instead, which removed a timing flake that had failed CI on a correct commit, cut that file from
eleven seconds to two, and made the budgets in it assertions about the run rather than bets on
how loaded the machine is.

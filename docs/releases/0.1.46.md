# LocalAi 0.1.46

[Русская версия](0.1.46.ru.md)

This release closes the backlog opened by benchmarking 0.1.45 against a fresh machine. The
theme running through it: what the toolkit does to a machine is now written down, reversible
where that is honest, and named plainly when it fails. An installation that stops half-way no
longer leaves a state nobody recorded; a failure line no longer arrives anonymous; an index
that covers nothing no longer calls itself precise.

**This release does not rebuild anything.** Chunk boundaries, the semantic format and the
generation identity are unchanged, so an existing index stays valid and no sync is required
beyond the ordinary one after a commit.

## The installer keeps a journal, and offers a rollback it can honestly deliver

The wizard applies real, machine-wide changes: winget installs, an activated version, runtime
files, MCP client registrations. Until now a run that failed or was cancelled part-way left the
machine in a state whose only record was a log line.

Every run now writes a journal to `%LOCALAPPDATA%\LocalAi-installer-logs` — the intent before
each effect, atomically and write-through, and the outcome after it — so a wizard killed
mid-install still leaves a record. After a failed or cancelled run the finish page offers
**Roll back changes**; the next start offers the same for a run that never got to finish. The
journal holds a live lock while its wizard runs, so a second wizard can tell a killed run from
one still installing in another window, and never offers to roll back work in flight.

Rollback undoes only what it can prove: an upgrade's activation returns through the launcher's
guarded pointer swap, and the residency policy, the Ollama launch record and the client
configuration files are restored only while they still hash to what the run wrote. What it
will not undo is named effect by effect — winget and npm installs are shared machine software,
pulled models live in Ollama's store, and a first installation's root holds runtime data as
soon as the broker runs. A successful run writes the journal and nothing else.

## Installing got easier to start and harder to derail

**A folder works where GitHub does not.** Download the manifest, its signature and the package
on a machine that has a route to GitHub, put the three in a folder, and point the installer at
it — or drop the installer into that folder and it offers the path itself. Nothing is trusted
for coming from a folder: the same embedded key verifies the manifest, the same SHA-256 checks
the package.

**Only Git and Ollama are required.** The .NET SDK, Node.js, Python and the two SCIP indexers
each buy precise navigation for one language, and each can be skipped — the page says what
skipping costs. Between them they are three to four gigabytes of machine-wide installs, which
is a poor thing to demand from somebody who wants semantic search over C#.

**winget is verified before every run.** The installer checks that the executable belongs to
the registered `Microsoft.DesktopAppInstaller` package, sits under a path only administrators
can write to, and is signed by Microsoft — and runs the path that check resolves, before each
install rather than once at detection.

**A placeholder cannot ship.** `--require-authenticode` refuses to sign while the publisher
policy is still the placeholder no file can match, instead of stamping a release every machine
would reject.

## Ollama being down is a waiting condition, not a failure

Queued work is kept, the broker retries, and a call that gives up says Ollama is not answering
and at which address instead of reporting a bare cancellation. Where the installer recorded a
verified Ollama, the broker starts it once — only that recorded executable, never one resolved
at the moment of use, and never for an endpoint on another machine.

## An index that covers nothing stops calling itself precise

A repository with C# where semantic indexing covered none of it used to finish `localai sync`
as a quiet success, and `index_status` called the generation precise because a `semantic.sidx`
existed. Now `sync` says so, `--require-semantics` turns the warning into a failure for a hook
or CI step, and `index_status` calls such a generation heuristic. When a repository has no
solution file and the project fallback loads one entry point, the projects left out are named
— partial coverage no longer reads exactly like full coverage.

## Failures name themselves

An unexpected CLI failure prints the exception type and the whole inner chain instead of the
outermost message alone — a bare `DllNotFoundException` used to print exactly "Dll was not
found." and nothing else. A workspace failure during semantic indexing names its kind and the
entry point being loaded. A Git failure names its cause instead of collapsing timeout, spawn
failure and non-zero exit into one message. `read_image` names the missing model instead of a
generic refusal, and a job the broker never ran says why it never ran.

## Documentation states the current facts

The living documentation — README, the developer overview, the tool reference — is rewritten
to describe the current state, in both languages, with the was/became narration removed. Dated
records that no longer earned their place in the tree — plans, design notes, old release
notes, benchmark reports — are removed; Git history keeps all of them. A code of conduct is
added, with a reporting route that does not run through the person being reported.

## Under the hood

The test suite runs on xunit v3, Roslyn workspace packages are aligned, and dependency updates
from Dependabot are folded in. The suite stands at 1768 tests.

# LocalAi 0.1.44

[Русская версия](0.1.44.ru.md)

One fix, found while installing 0.1.43: a build that resumes from its embedding checkpoint died
at the finish line, after every chunk of the corpus had already been embedded.

**This release does not rebuild anything.** Chunk boundaries, the semantic format and the
generation identity are unchanged from 0.1.43, so an index built by it stays valid and no sync is
required beyond the ordinary one after a commit.

## A resumed build could not finish

0.1.43 gave the semantic phase a checkpoint of its own, which is what made resuming an
interrupted sync reach the embedding stage at all. It reached it, and then failed there.

The counter starts at the number of chunks the embedding checkpoint restored, and it was compared
against the number of chunks still queued. Those two differ by exactly the number restored, so
the report crossed over near the end:

```
Embedded 20845/20980 chunks (12.1/s, ~0.2 min left)
Embedded 21075/20980 chunks (12.1/s, ~-0.1 min left)
localai: Repository progress is invalid.
```

The progress store rejects a count above its own total and rejects a negative estimate. That
record is both, so it threw — and the sync died with nothing published, having embedded all
26 119 chunks of a large repository. Half an hour of GPU time, discarded at the finish line.

The checkpoint left behind made it worse rather than better. On the next attempt the restored
count exceeded the remaining queue immediately, so the same build failed within seconds instead
of within half an hour, and no number of retries could complete it. The way out was to delete the
embedding checkpoint and pay for the whole corpus again.

The denominator is now what the whole build has to produce — the same number the restore report
one screen above already used. A resumed build reports a count that only rises, an estimate that
only falls, and finishes.

## Upgrading

Install with the GUI installer from this release. Nothing else is needed: no rebuild, no
resynchronisation, no change to any index on disk.

If you are sitting on an interrupted 0.1.43 build that will not finish, this release is the fix
for it: the leftover checkpoint becomes usable again, and the build resumes and completes instead
of failing on its first progress report.

## Verification

The complete solution ran 1 839 tests: 1 835 passed and four skipped for platform reasons.

The resume test existed before this and asserted that the restore is reported. It never looked at
the records the embedding loop emits, which is where the arithmetic was wrong. It now asserts what
the progress store will actually accept — every record within its total, no negative estimate, and
a final record that is complete. Without the fix it fails with `ProcessedChunks = 40,
TotalChunks = 33, EstimatedRemaining = -00:00:00.0019`: the same shape as the production failure,
three orders of magnitude smaller.

# LocalAi 0.1.52

[Русская версия](0.1.52.ru.md)

This release is about who is reading. Everything the product prints now arrives in the language
of the machine it runs on, and everything it prints to a *program* arrives in one versioned
envelope that never changes language at all. Between those two the console grew the commands it
was missing, an indexing run stopped reloading the model between every batch, and the parts of
the runtime that fail learned to write down why.

**This release does not rebuild anything.** Chunk boundaries, the semantic format, the index
container and the embedding model are unchanged; an existing index stays valid and installing
this release triggers no re-embedding.

## Everything answers in the language the reader reads

A Russian system now gets Russian, everywhere: the search and navigation tools, the whole
`localai` console, the installer, the index core, the broker's own refusals. Where a language
has no translation the answer is English, and nothing is half-translated — a parity test refuses
a release carrying only some of the keys for a language.

What never translates, in any language, is what a machine reads or a person retypes: commands
and their options, status tokens such as `CONFIGURED`, `STALE` and `INITIALIZING`, enum values,
identifiers, paths, wire formats and the field names of every JSON shape. Numbers, durations and
dates stay invariant too, because agents quote those lines verbatim.

The two faces are deliberately opposite. The MCP tools follow the reader, so the same refusal
from the same index core reaches you in Russian through `search_code` and in English through
`codesearch search`. One is read by a person; the other is parsed.

## The console can now do what the MCP tools do

The whole local-model capability was reachable only through MCP. Four commands close that:

```powershell
localai ask "In one sentence: what does this file do?" --file src/Foo.cs
localai triage --file build.log
localai read-image --file screenshot.png
localai translate --file README.md --from English --to Russian --out README.ru.md
```

They run through the same broker queue, the same residency policy and the same bounded fragment
loop as the MCP tools — not a second path with its own rules. `translate` takes `--out` because
its output is a document rather than an answer, and every translation carries a paragraph naming
the model that produced it.

One command answers what each console can be driven to do at all:

```powershell
localai capabilities --json
codesearch capabilities --json
```

## A face a program can read

`--json` is the other face, and it is one shape for both binaries:

```json
{"schema":1,"command":"doctor","ok":true,"data":{"verdict":"Ok","failed":0,"warned":0,"checks":[…]}}
```

`schema`, `command`, `ok`, `data`, `error` — a plugin writes one parser for `localai` and
`codesearch` alike. Asking for JSON also fixes the language to English, because output that is
versioned cannot follow the machine it came from. A command that does not answer `--json`
refuses it rather than printing prose, so the promise holds without exception: if the flag was
passed, standard output is an envelope.

Today those are `localai repo status`, `doctor`, `ask`, `triage`, `read-image`, `translate` and
`capabilities`, and `codesearch search`, `get-chunk`, `status` and `capabilities`.

`doctor --json` is worth a line of its own. It exits 1 when a check failed — a verdict about the
machine — and stays `ok: true`, with the failed checks inside `data`, where a caller asking about
the health of an installation needs them. Every fact a check states inside a sentence is
published as a field of its own: the process id, the queue depth, the generation id, the values
of each policy. `ok: false` is kept for a run that produced no answer at all.

## An indexing run that stops reloading the model

The broker keeps a model resident only while its queue holds work for it, and an indexing run
posted the next batch only after the previous one had answered — so the queue was empty for a
moment between every two batches, the model was unloaded, and the next batch began by loading it
again. Measured on one repository: 3.9 seconds of an 11.9-second batch, and about a third of the
run.

A run now keeps one batch in flight, so the queue never runs dry mid-sync. Nothing in the broker
or in the residency policy changed; the rule that keeps a model loaded while work for it is
queued simply has something to see.

## When something fails, the runtime writes down what

Three things that were happening silently:

- **The broker keeps its own failures.** `diagnostics.jsonl` under the runtime root, one JSON
  object per line, bounded by size with one rotation kept, so the first failure of a run survives
  its hundredth. They used to go to a stream nothing captured.
- **A failed job keeps what it was refused with.** The sentence a backend answers with — bounded,
  and redacted of the request — is recorded beside the job, carried on the exception the caller
  catches, and written into the diagnostics log. It used to be discarded three times over, leaving
  an exception type and nothing else.
- **`doctor` tells a queue that is busy from one that has stopped.** A queue that had not moved in
  two hours looked exactly like a working one, and the state files already carried what was needed
  to tell them apart.

`doctor` also stopped reporting a policy file that quietly does nothing as a configured one. Every
policy store answers a document it cannot use — malformed, an unknown schema, a value out of range
— with its safe defaults, so a file that had stopped counting stayed on disk looking configured.
That case is now a note that names the file.

## Disk: one generation, and the overlays nothing can read

A repository kept three published generations and every overlay hanging off them. It now keeps
the current one, and a generation the pointer has already moved past goes when it is superseded
rather than a day later — while anything that may still *become* current keeps its grace, so a
sweep during a build cannot delete what that build is producing. Overlays belonging to worktrees
that no longer exist, and to commits nobody is on, are collected from the generation that stays.

`localai prune` also stopped ending a whole run on one repository record it could not read, and
stopped removing a record whose drive is merely offline.

## Navigation takes the numbers search prints

`search_code` prints one-based lines and the navigation tools took zero-based ones, with nothing
converting between them: a pasted line landed one line into the body — a refusal when nothing was
there, and a confident answer about the wrong symbol when something was. Both ends now count from
one, and a test composes them end to end: a real hit, handed to `go_to_definition` unchanged.

A path that is not repository-relative is refused by name at the edge, in the reader's language,
instead of arriving as a framework exception in English.

## The installer follows the system theme

Light and dark palettes taken from the Windows setting and followed live, and a way back from
every page of the wizard.

## Upgrading

Nothing to do beyond installing it. The runtime layout, the manifest format and the signing key
are unchanged, indexes are kept, and settings are read from the same place.

```powershell
localai update            # refuses while the broker has queued jobs
localai update --wait     # waits for them to finish first
```

## Verification

```powershell
localai doctor
localai doctor --json
```

The first line of the report names the installed version; `--json` answers the same thing in one
envelope, and now carries `releaseVersion` beside the directory the pointer holds.

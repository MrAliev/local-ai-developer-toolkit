# LocalAi 0.1.53

[Русская версия](0.1.53.ru.md)

This release is about waiting. Everything long now says where it has got to — a translation
counts its fragments, a log triage counts what it has read, a model download counts gigabytes,
and a job sitting in the broker's queue says it is queued rather than pretending to work. Two
faults that only silence had hidden came out with it: a large model could not finish installing
at all, and one unroutable job stopped every other job on the machine.

**This release does not rebuild anything.** Chunk boundaries, the semantic format, the index
container and the embedding model are unchanged; an existing index stays valid and installing
this release triggers no re-embedding.

## A long run says where it is

Four commands used to go from the command line to the answer in silence. They now report, on
standard error, leaving standard output for the answer itself:

```
'R:\LocalAi\docs\overview.md' is Markdown, so --markdown is on: fenced code passes through
untranslated. Pipe the file in to translate it as plain text.
Translating fragment 1 of 21.
Translating fragment 2 of 21. About 4.7 min left.
```

`translate` knows its total before the first call and says so before the first call. `triage`
cannot — fragments are streamed off the log — so it counts without a denominator instead of
inventing one, and prints the total at the first moment that total is true. `ask` and
`read-image` are one model call and count nothing.

Under all four, a job that has not finished is waiting for one of two different things, and the
line says which: `Waiting in the broker queue` is another client or a stalled broker; `The model
is working` is a slow model. Those are different faults with different remedies, and the queue
wait used to be invisible until the run was over.

A line appears only into silence — the first after ten seconds of a run that has said nothing,
then whenever thirty seconds pass with no line at all. Every line is written whole: nothing
rewrites itself with a carriage return, so a redirected log holds the same bytes a terminal
showed.

## A document can be translated by name

`translate` took a phrase or a pipe and nothing else, so a file had to be piped in — and a pipe
is not a way to hand this command a document. The console sets its output encoding and never its
input encoding, so a piped UTF-8 file was decoded with the console's code page and Cyrillic
reached the model already mangled. There was no correct route at all.

```powershell
localai translate --in README.md --from English --to Russian --out README.ru.md
```

`--in` is the pair of `--out`: one reads the document, the other writes it. It reads UTF-8 with
BOM detection. `--in -` is standard input, for a wrapper that passes either. A `.md` or
`.markdown` file is translated with `--markdown` whether or not the flag was given, and the
command says so before the run starts. `--in` and `--out` naming the same file is refused:
translating in place destroys the original and there is no undo.

## A download says how far it has got

`localai model pull` downloaded gigabytes and printed one line when it was over. It could not
have done better — the pull was not streamed, so the size was known only inside a call that said
nothing until it ended.

```
Downloading gpt-oss:20b: 4.7 of 12.8 GB.
```

Two figures and never a percent. The total is the sum of the layer sizes named so far, so it
grows as layers appear, and a percent against a growing denominator goes backwards. Both figures
only ever increase, and three identical lines thirty seconds apart mean the download has stalled
— which is information a percent hides behind rounding.

The installer shows the same figures in its own words, in its own language, and its run log keeps
one line a phase rather than one a second.

## A large model can now be installed at all

`localai model pull` gave up after thirty minutes and reported a cancellation nobody had asked
for, while the broker went on downloading. The installer allows twelve hours. A 12.8 GB model on
an ordinary connection therefore failed to install, and nothing connected that to the speed of
the connection, because the download was silent. The pull now gets the same twelve hours the
installer allows it.

## One job can no longer stop every job

A job naming a model the routing catalogue does not hold — `localai ask "hi" --model
no-such-model:1b` — stopped the queue. Not slowed: stopped. Nothing was leased at any priority
for as long as that job stayed queued, including the embedding job a Git hook posts, so a
`git commit` could wait ten minutes behind a job nothing had even attempted. The broker reported
itself healthy throughout.

The job is now skipped for scheduling, leased anyway, attempted once, and fails with a reason
that names the model. Everything else is served while it waits.

## A refusal that was never about the request

An embedding batch could fail with HTTP 400 and no explanation. Forty did in four days. The 400
was not about the batch: it was the backend reporting that it could not reach its own runner,
and the same request worked moments later — while the layer above answered by halving the batch
to isolate an offending chunk that did not exist, failing twice where it could have waited once.
That refusal is now retried, and a 400 that really is about the request is still refused at once.

## Upgrading

Install over the top; nothing needs uninstalling first. The index is untouched and no model is
re-downloaded. Restart your editor or agent afterwards so its MCP servers pick up the new
binaries — until they restart they answer from the previous version, and the tool descriptions
they show are the previous version's too.

## Verification

The full suite runs on Windows in CI: 2806 tests. Every behaviour above is covered by tests that
were written before the code and shown to fail without it; where that order was not kept, the
failure was reconstructed afterwards by removing the fix and confirming the test reddens.

What was **not** verified before publishing: the streamed download and the retried refusal
against a live broker. The broker on the machine that built this was the previous release, so
those two paths are covered by tests at every layer and by nothing else. The first thing worth
watching after installing is a sync log with no "halving the batch" line in it.

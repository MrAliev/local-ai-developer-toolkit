# LocalAi 0.1.29

[Русская версия](0.1.29.ru.md)

This release comes out of a full inspection of an installed 0.1.28. Every item below was
observed on a real machine rather than reasoned about, and three of them turned out to have a
different cause than the symptom suggested.

## Bound what the runtime root keeps

The runtime had reached 40.8 GB with no retention anywhere: 20 GB of archived job responses
across 8311 terminal jobs, 9.5 GB of index generations, 9.7 GB of installed versions and 1.4 GB
of launcher backups.

- Retention bounds now live in `%LOCALAPPDATA%\LocalAi\retention.json`, read by the broker, the
  CLI and the installer alike.
- The broker applies the archive bounds continuously — throttled to one pass a minute and capped
  per pass, so the queue never stalls behind housekeeping. It drops the response body and keeps
  the request and state documents as the audit trail.
- `localai prune [--dry-run]` reclaims a backlog in one pass and reaches what the broker does not
  own: generations, the overlays keyed to them, installed versions, launcher backups, job
  telemetry, and repository records whose checkout no longer exists.
- `ResponseGraceMinutes` is a correctness floor, not a preference: nothing may remove a response
  body inside it whatever the other bounds ask for, and a hand-edited zero is clamped.
- Nothing in use is removable by construction — not the generation a repository's pointer names,
  not the version `bin\current.json` names, not a version whose files a running tool still has
  mapped.

## Accept the local symbol ids scip-python actually emits

Re-syncing any repository containing Python failed outright with `SCIP local symbol ID is
invalid`, and a failed adapter blocks the whole generation — so those repositories could not
publish an index at all. This is why several stayed on the previous index format.

`scip-python` 0.6.6 emits ids like `local 16(line)`, which the SCIP grammar does not allow. The
importer now enforces what actually has to hold — no whitespace or control characters, because
the id is joined to its document path — and names the offending id when it does reject one.

## Report the phases an index build spends its time in

A generation was built at 20:32:32 and the pointer moved to it at 20:35:02, while `index_status`
reported `EmbeddingBase` at `1415/1415 chunks (0 remaining)` throughout. That reads as a finished
index refusing to publish; in fact two slow phases run after embedding and neither reported
anything.

- New phases `SemanticBase`, `PublishingGeneration` and `SemanticOverlay`.
- Chunk counters are cleared when a phase that does not count chunks begins, and `index_status`
  prints `not counted in this phase` instead of the previous phase's finished tally.
- The staleness line names an unfinished sync when one is recorded, without claiming the process
  behind it is still alive.

## Say why navigation fell back to text matching

A repository last synced before semantic indexing shipped carries no `semantic.sidx`, so
`find_references` answered with README and docs matches — every hit correctly tagged `Heuristic`,
nothing saying why. The gateway already built the explanation and discarded it to reach the
fallback.

- Navigation results carry the reason alongside the locations; MCP prefixes a degraded answer
  with `semantic_navigation_degraded:`.
- `index_status` gained a `Navigation:` line that names the re-sync command.
- A missing semantic index and an index with no symbol at that position are worded apart,
  because only one of the two is repaired by re-syncing.

## Give every MCP tool a row in the Codex configuration

Codex writes a per-tool row when a tool is first approved, and a tool without a row resolves to
`auto`, which prompts for any tool that declares no annotations — which is all of them. A
long-lived installation carried rows for eleven of the twenty tools.

The installer now writes the missing rows and a `default_tools_approval_mode` server default, so
a tool added by a later release is covered the moment it exists. Only what is missing is written:
an existing row or server default is left exactly as the user wrote it, including one that
refuses the tool. Tests reflect over each server's tool attributes, so a new tool cannot ship
without its row.

## Stop the experiment report from eating its own evidence

`local_models_status` reported `CompletedAttempts: 6` while `local_model_experiment_report`
reported `Attempts: 1` for the same pair. Reading the report deleted telemetry older than seven
days, so consulting it discarded the history it was reporting on.

Reading no longer deletes — the bound is applied by the write that records a new task. The report
takes attempts, successes and errors from the experiment state, and `ObservedTasks` says how many
telemetry records the timings rest on.

## Say when a job was too small to save anything

`read_image` on a 336x52 image reported `Сэкономлено примерно 0 облачных токенов`. The arithmetic
was right — that image is worth about two dozen tokens to look at directly — but a bare zero
reads as a broken counter rather than as a job not worth delegating. The notice now states the
saving as a sentence.

## Also

`localai hook` was missing from the usage text while every installed Git hook invoked it, so
anyone debugging a hook was told the command they had just run did not exist. It is listed now,
along with `policy` and `semantic`, and `localai hook` without an event names the events.

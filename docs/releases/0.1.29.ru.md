# LocalAi 0.1.29

[English version](0.1.29.md)

Этот релиз вышел из полной проверки установленной 0.1.28. Каждый пункт ниже наблюдался на
реальной машине, а не выведен рассуждением, и у трёх из них причина оказалась не той, на которую
указывал симптом.

## Ограничено то, что накапливает runtime

Runtime дорос до 40.8 ГБ без какого-либо удержания: 20 ГБ архивных ответов на 8311 терминальных
заданий, 9.5 ГБ поколений индекса, 9.7 ГБ установленных версий и 1.4 ГБ резервных копий launcher.

- Границы удержания живут в `%LOCALAPPDATA%\LocalAi\retention.json` и читаются брокером, CLI и
  установщиком одинаково.
- Брокер применяет архивные границы постоянно — не чаще раза в минуту и с ограничением работы за
  проход, поэтому очередь не простаивает за уборкой. Тело ответа удаляется, request и state
  остаются как след того, что выполнялось.
- `localai prune [--dry-run]` разбирает накопившееся за один проход и дотягивается до того, чем
  брокер не владеет: поколений, привязанных к ним overlay, установленных версий, резервных копий
  launcher, телеметрии заданий и записей репозиториев, чей checkout больше не существует.
- `ResponseGraceMinutes` — это пол корректности, а не предпочтение: ни одна другая граница не
  может удалить тело ответа внутри него, а отредактированный вручную ноль зажимается.
- Ничто используемое не удаляется по построению: ни поколение, на которое указывает манифест
  репозитория, ни версия из `bin\current.json`, ни версия, чьи файлы загружены работающим
  инструментом.

## Принимаются идентификаторы local-символов, которые scip-python выдаёт на самом деле

Пересборка любого репозитория с Python падала с `SCIP local symbol ID is invalid`, а отказ
адаптера блокирует всё поколение — поэтому такие репозитории вообще не могли опубликовать индекс.
Именно из-за этого несколько из них остались на прежнем формате.

`scip-python` 0.6.6 выдаёт идентификаторы вида `local 16(line)`, чего грамматика SCIP не
допускает. Импортёр теперь проверяет то, что действительно должно выполняться — отсутствие
пробельных и управляющих символов, потому что идентификатор склеивается с путём документа, — и
называет виновный идентификатор, если всё-таки отвергает его.

## Фазы сборки индекса стали видимыми

Поколение было собрано в 20:32:32, а указатель переехал на него в 20:35:02, и всё это время
`index_status` показывал `EmbeddingBase` при `1415/1415 chunks (0 remaining)`. Это читается как
готовый индекс, отказывающийся публиковаться; на деле после эмбеддинга идут две медленные фазы, и
ни одна не отчитывалась.

- Новые фазы `SemanticBase`, `PublishingGeneration` и `SemanticOverlay`.
- Счётчики чанков очищаются при переходе в фазу, которая их не считает, а `index_status` пишет
  `not counted in this phase` вместо застывшего итога предыдущей фазы.
- Строка устаревания называет незавершённый sync, если он записан, ничего не утверждая о том, жив
  ли стоящий за ним процесс.

## Сообщается, почему навигация откатилась на текстовый поиск

Репозиторий, не пересобранный с момента появления семантической индексации, не содержит
`semantic.sidx`, поэтому `find_references` отвечал совпадениями из README и docs — каждое честно
помечено `Heuristic`, но без единого слова о причине. Gateway уже строил объяснение и выбрасывал
его, чтобы дойти до fallback.

- Результаты навигации несут причину вместе с локациями; MCP предваряет деградировавший ответ
  строкой `semantic_navigation_degraded:`.
- В `index_status` появилась строка `Navigation:` с командой пересборки.
- Отсутствующий семантический индекс и индекс без символа в этой позиции сформулированы
  по-разному, потому что re-sync лечит только одно из двух.

## Каждый инструмент MCP получил строку в конфигурации Codex

Codex записывает строку инструмента при первом одобрении, а инструмент без строки попадает на
`auto`, который требует подтверждения для любого инструмента без объявленных аннотаций — то есть
для всех. На долгоживущей установке было одиннадцать строк из двадцати.

Установщик дописывает недостающие строки и серверный дефолт `default_tools_approval_mode`, чтобы
инструмент из будущего релиза покрывался сразу, как появится. Записывается только отсутствующее:
существующая строка или серверный дефолт остаются ровно такими, какими их написал пользователь,
включая запрещающие инструмент. Тесты читают атрибуты инструментов каждого сервера рефлексией,
поэтому новый инструмент не может выйти без своей строки.

## Отчёт об экспериментах перестал уничтожать собственные данные

`local_models_status` показывал `CompletedAttempts: 6`, тогда как
`local_model_experiment_report` для той же пары показывал `Attempts: 1`. Чтение отчёта удаляло
телеметрию старше семи дней, то есть просмотр уничтожал историю, о которой отчёт сообщает.

Чтение больше не удаляет — граница применяется записью новой задачи. Отчёт берёт попытки, успехи
и ошибки из состояния эксперимента, а `ObservedTasks` говорит, на скольких записях телеметрии
держатся тайминги.

## Сообщается, когда задача была слишком мелкой, чтобы что-то сэкономить

`read_image` на изображении 336×52 сообщал «Сэкономлено примерно 0 облачных токенов». Арифметика
была верна — такое изображение стоит около двух десятков токенов при прямом просмотре, — но
голый ноль читается как сломавшийся счётчик, а не как задача, которую незачем делегировать.
Теперь экономия сообщается предложением.

## Кроме того

`localai hook` отсутствовала в строке usage, хотя её вызывает каждый установленный Git-хук, —
поэтому любой, кто отлаживал хук, узнавал от самого инструмента, что только что выполненной
команды не существует. Теперь она перечислена вместе с `policy` и `semantic`, а `localai hook`
без события называет поддерживаемые события.

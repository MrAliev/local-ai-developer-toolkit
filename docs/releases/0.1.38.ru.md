# LocalAi 0.1.38

[English version](0.1.38.md)

Обновление больше не требует вручную гасить рантайм, а релиз, ассеты которого отказывается
скачивать GitHub CLI, всё равно можно установить.

## Обновление больше не отказывает машине, которую обновляет

Захват installation layout открывал каждый его каталог с `FILE_OPEN_IF` и просил на каждом право
`DELETE`. Windows отказывает в `DELETE` на каталоге, который другой процесс держит без
`FILE_SHARE_DELETE`, а runtime root — ровно такой каталог, пока работает broker: это его рабочий
каталог. В результате установка на машину, где LocalAi уже использовался, останавливалась на самом
первом шаге проверки, и всё, что сообщалось, — `check: OpenRelative`.

Расчищать себе дорогу установщик умел всегда: он просит launcher, который сам же собирается
поставить, остановить работающие инструменты, и только потом их заменяет. Этот шаг находился
несколькими шагами дальше проверки и потому был недостижим. Теперь `DELETE` запрашивается только на
каталогах, которые установка создаёт сама, — их же она и удаляет, если установка сорвалась до
фиксации; уже существующие каталоги открываются без этого права. Проверка перестала быть тупиком, и
дальше срабатывает прежняя логика «остановить и повторить»: закрывать клиентов или гасить broker
перед обновлением больше не нужно.

Отказ при открытии каталога теперь называет каталог и NTSTATUS — если layout действительно
недоступен, видно, какой именно каталог и почему, а не только имя сработавшей проверки.

## Релизы, которые CLI не может скачать

`gh release download` на некоторых релизах падает, даже когда машина авторизована и ассет
существует. В этом случае установщик определяет релиз через GraphQL, читает список ассетов по REST
API и скачивает ассет по числовому идентификатору. Байты ассета идут из процесса прямо в файл, а не
через текстовый ридер, который портит произвольные байтовые последовательности; скачанный файл
принимается, только если его длина совпадает с размером, о котором сообщает GitHub. В сообщении об
ошибке приводятся обе причины — исходная и запасная, — поэтому настоящая проблема с авторизацией
по-прежнему читается как одна.

## Обновление

Установите версию GUI-инсталлятором из этого релиза. Он сам останавливает broker и работающие
MCP-серверы, заменяет их и активирует новую версию; закрывать что-либо заранее не нужно. Клиенты
переподключатся при следующем запросе. Установщик, скачанный до этого релиза, всё ещё несёт старую
проверку — возьмите этот.

## Проверка

Полный набор решения прошёл 1 775 тестов с четырьмя платформенными пропусками.

Путь отказавшего обновления закреплён тестами, которые удерживают каталог ровно так, как Windows
держит рабочий каталог живого процесса: layout принимается, пока этот handle открыт; по-настоящему
недоступный каталог по-прежнему отклоняется — с путём и NTSTATUS; а сорвавшаяся установка всё так же
убирает созданный ею scaffold.

# LocalAi 0.1.30

[Русская версия](0.1.30.ru.md)

Two defects found by a diagnostic run of the installed 0.1.29. Neither corrupts data or returns
wrong results — both are cases of the system doing the right thing and reporting it wrongly,
which is why they survived a release that was otherwise verified end to end.

## Stamp the version being released

Every binary in 0.1.29 reported `0.1.22`. The tag, the installed version directory and the
package all said 0.1.29, and the commit hash embedded in the informational version was correct;
only the declared version disagreed.

`Directory.Build.props` hardcodes the version and had not been updated in six releases. Raising
the number there is the fix that had already failed six times, so the release script now stamps
the version it was told to build:

```powershell
-p:Version=$ReleaseVersion -p:VersionPrefix=$ReleaseVersion `
-p:AssemblyVersion="$ReleaseVersion.0" -p:FileVersion="$ReleaseVersion.0" `
-p:InformationalVersion=$ReleaseVersion
```

That is the only value that can be right by construction. The property remains as the fallback
for a local build and is brought up to date.

## Match a path filter written with either separator

`pathContains` compared the filter to the indexed path with a plain `IndexOf`. An index built on
Windows stores backslashes, while every other surface of this project writes forward slashes —
its own search output, its documentation, its CLI examples. So `docs/releases` matched nothing
and `docs\releases` matched everything.

The failure was invisible: a filter that matches nothing looks exactly like a filter with no
hits, so the result gave no hint that the separator was the reason. Both sides are now reduced
to one separator, and the filter is normalised once rather than per chunk.

## Also in this release

The release script published into whichever directory the process happened to start in, because
`Set-Location` moves the PowerShell location while `dotnet publish` and `Path.GetFullPath` follow
the process one. Run from a worktree it published into the wrong tree and then failed at
`Required release artifact is missing` immediately after reporting seven successful publishes.

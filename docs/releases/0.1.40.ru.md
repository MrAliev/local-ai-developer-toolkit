# LocalAi 0.1.40

[English version](0.1.40.md)

Git-хуки теперь ставятся туда, где git их действительно запускает. В любом репозитории, где задан
`core.hooksPath` — а это почти каждый фронтенд, — они записывались в каталог, который git не
читает, и индекс тихо переставал следовать за HEAD.

## Хуки уезжали в каталог, который git игнорирует

`localai hooks install` писал диспетчеры в `$GIT_DIR/hooks` и сообщал об успехе. Но если в
репозитории задан `core.hooksPath`, git этот каталог не смотрит вовсе, а задают его и husky, и
lefthook, и simple-git-hooks — причём husky делает это из `npm install`, через скрипт `prepare`,
без чьего-либо решения. Установка проходила, хуки больше не срабатывали, и никто об этом не
сообщал: единственным симптомом было отставание индекса в `index_status` — для того, кто
догадается туда посмотреть.

Теперь путь берётся из `core.hooksPath`, включая относительный: он разрешается от корня рабочего
дерева, как это делает сам git, и от общего каталога репозитория, если рабочего дерева нет.

С husky нужно ещё одно действие, и именно поэтому правка не в одну строку. Он указывает
`core.hooksPath` на `.husky/_` — каталог, который сам же удаляет и создаёт заново при каждом
запуске, так что записанный туда диспетчер исчез бы при следующем `npm install`. Его шимы
запускают `.husky/<hook>`, причём для всех стандартных хуков, независимо от того, есть такой файл
или нет, — туда наши и идут. Каталог опознаётся по лежащему внутри `h` или `husky.sh`, а не по
имени, поэтому обычный каталог с именем `_` остаётся нетронутым.

Диспетчеры, попавшие в рабочее дерево, дописываются в `.git/info/exclude`, а не висят
неотслеживаемыми файлами в репозитории, чей `.gitignore` принадлежит не нам. Этот файл локален
для клона и не отслеживается ничем — правильное место для решения, которое принял инструмент, а
не проект.

**Если вы ставили хуки в репозиторий с husky до этой версии, выполните `localai hooks install`
ещё раз.** Старые диспетчеры в `$GIT_DIR/hooks` безвредны и просто ничего не делают, а если
репозиторий когда-нибудь перестанет задавать `core.hooksPath`, они снова заработают.

## Что SCIP на самом деле даёт для нарезки по символам

Задача #82 — резать TypeScript и Python по символам вместо окна в 60 строк — опирается на то,
что внешние индексаторы сообщают границы тела определения. Никто не проверял, сообщают ли.
В этот релиз входят фикстуры, которые отвечают на вопрос, — `tests/CodeSearch.Tests/Fixtures/SymbolChunking` —
и читатель без зависимостей, который считает ответ по реальному индексу, а не по схеме SCIP.

Поле `enclosing_range` отдают оба адаптера. Из определений, у которых есть тело, `scip-python`
0.6.6 снабжает диапазоном все — включая вложенные функции и определения с декоратором.
`scip-typescript` 0.4.0 снабжает каждое определение, которому даёт глобальный символ, и ни одно
из двух исключений: объявленные внутри тела функции и те, чей инициализатор — вызов, то есть
`export const X = memo(() => …)`. На репозитории React из 2 653 файлов это 2 991 диапазон,
покрывающий 67% непустых строк, при 955 файлах, где тела определений нет вовсе.

Сама нарезка в этом релизе не менялась. Результат записан потому, что он сужает обещания #82, а
фикстуры закоммичены, чтобы обновление адаптера, меняющее ответ, проявилось как упавшее
измерение, а не как молча изменившиеся границы чанков.

## Обновление

Устанавливайте GUI-установщиком из этого релиза. Он сам останавливает брокер и запущенные
MCP-серверы, заменяет их и активирует новую версию. Для репозиториев, куда хуки ставились до этой
версии и где задан `core.hooksPath`, выполните `localai hooks install` ещё раз; остальных это не
касается, и делать ничего не нужно.

## Проверка

Полное решение прошло 1 784 теста при четырёх пропусках, зависящих от платформы. Среди них пять
новых случаев на выбор каталога хуков: `core.hooksPath` соблюдается; каталог, который husky
пересоздаёт, перенаправляет на родительский; обычный каталог `_` — нет; диспетчеры в рабочем
дереве попадают в исключения ровно один раз при повторных установках; хукам внутри каталога git
исключение не требуется.

Тесты запускающего процессы кода больше не поднимают для этого PowerShell — вместо него
небольшая программа, написанная под задачу. Это убрало флейк по времени, из-за которого CI падал
на корректном коммите, сократило файл с одиннадцати секунд до двух и вернуло его бюджетам смысл:
теперь это утверждения о прогоне, а не ставки на загруженность машины.

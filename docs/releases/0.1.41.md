# LocalAi 0.1.41

[Русская версия](0.1.41.ru.md)

`localai repo status` can be asked about a repository the way every other command can. Until
now it answered `NOT_CONFIGURED` about configured repositories whenever it was asked with
`--root`, which is how the instruction block tells agents to address every other command.

## A wrong answer that read as a confident one

The command took its first argument as a Git common directory whatever that argument was. Every
other command here locates a repository with `--root`, so that is what anyone reaches for — and
`repo status --root D:\repo` hashed the literal string `--root` into a repository id nobody had
ever configured, printed `NOT_CONFIGURED`, and exited 0.

It was found while verifying the 0.1.40 installation: the command reported LocalAi's own
repository as unconfigured while that repository's index was current at HEAD and its Git hooks
were firing.

The wrong answer is the expensive kind. The instruction block installed into `CLAUDE.md` and
`AGENTS.md` tells an agent to run this command when it opens a repository, and to offer the
whole kit — generations, overlays, hooks, client registration — if the answer is
`NOT_CONFIGURED`. So the failure mode was an assistant offering to set up a repository that has
been indexed for weeks.

`--root <dir>` is now accepted and resolved through Git, the way `sync`, `hook`,
`hooks install` and `doctor` resolve it, and a bare Git common directory still works. An
argument the command does not recognise is refused with a message and exit code 2 rather than
read as a path; a path that is not a directory says so instead of being answered about.

The instruction block itself now shows the `--root` form. It is read by agents that are not
standing in the repository they are asking about, and the bare form answers about whatever
directory the process happens to be in.

## Documentation checked against a running installation

Every claim below was checked against 0.1.40 as installed, not against memory:

- Both READMEs were missing four projects that exist: `LocalAi.Broker.Core`,
  `LocalAi.Installer`, `LocalAi.Installer.Core` and `LocalAi.ReleaseSigner`. The first is
  described two sections above the table it was missing from.
- The Russian project table had been machine-translated past the point of meaning something
  else — "chunking, embeddings" had become "trimming, attachments", "contracts" had become
  "contacts". It is written in Russian now.
- The developer overview said hooks are installed without saying where. It now states the rule
  0.1.40 shipped: `core.hooksPath` when the repository sets one, `.husky` rather than the `_`
  directory husky regenerates, an existing hook chained rather than replaced, and dispatchers
  that land in the working tree excluded through `.git/info/exclude`.

The rest was checked and left alone: the tool inventories still match what the servers expose,
and the per-language chunking statements corrected in 0.1.39 are still accurate.

## Upgrading

Install with the GUI installer from this release. The instruction block in `CLAUDE.md` and
`AGENTS.md` is rewritten between its markers, so the corrected command form arrives with the
installation; anything outside those markers is preserved. Restart the client to pick it up.

Nothing needs re-running in any repository. If you were told a configured repository was not
configured, ask again.

## Verification

The complete solution passed 1,794 tests with four platform-dependent skips. Ten of them are
new, covering what the command accepts and what it refuses: `--root` resolved through Git, a
bare common directory, an unknown option, `--root` with nothing after it, and two repositories
in one invocation. The four real invocations were also run against the two repositories on the
machine this was found on.

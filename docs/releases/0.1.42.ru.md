# LocalAi 0.1.42

[English version](0.1.42.md)

TypeScript и Python режутся по символам. Результат поиска в `.ts` или `.py` — это определение с
именем, а не `payments.ts [3/10]` с границей там, где случайно оказалась строка 48·k.

**Этот релиз один раз пересобирает индекс каждого репозитория.** Границы чанков входят в
идентичность поколения, поэтому первая же синхронизация после установки строит базовое поколение
заново. Прочитайте раздел «Обновление» до того, как её запустить.

## Что теперь представляет собой результат

C# режется по синтаксису с самого начала; всё остальное шло 60-строчным окном с перекрытием в 12
строк и без всякого представления о том, что оно только что разрезало. Окно не ломалось заметно —
оно давало векторы, описывающие хвост одной функции и голову следующей, а такая ошибка проявляется
только как ухудшение выдачи.

Теперь TypeScript и Python режутся по границам определений, которые сообщают внешние индексаторы.
Определение становится чанком с настоящим символом, сигнатурой и точными строками. Определение,
содержащее другие, сохраняет свои строки и перечисляет вложенные по первой строке — так же, как
чанк типа в C# перечисляет сигнатуры членов, а не повторяет их тела, — поэтому ни одна строка не
эмбеддится дважды.

Всё, что не покрыто определением, остаётся на окне: импорты, код уровня модуля, промежуток между
двумя функциями. Ничего не выпадает из индекса и ничего не приклеивается к соседнему символу.

Две формы остаются на окне сознательно, потому что `scip-typescript` не сообщает для них границ
тела: определение внутри тела функции и объявление, инициализированное вызовом, — то есть
`export const X = memo(() => …)`. Это измерено до того, как что-либо было построено, в задаче #87,
а не выведено из схемы SCIP.

Если внешний индексатор не установлен, выключен политикой или упал, файл режется ровно так, как
резался раньше. Этот путь закрыт тестом, который сравнивает выдачу запасного пути чанк в чанк с
прежним чанкером.

## Что показали измерения

Репозиторий на React из 2 653 файлов, двенадцать кейсов на естественном языке, один и тот же
коммит, проиндексированный обоими способами:

| | До | После |
|---|---:|---:|
| Precision@5 | 0.116667 | 0.116667 |
| Recall@10 | 0.750000 | 0.750000 |
| Средний ранг первого релевантного | 5.500000 | 4.916667 |
| Символов в ответах | 70 245 | 66 087 |
| Попаданий с именем символа в TypeScript/Python | 0 из 86 | 33 из 85 |
| Строк исходника в этих попаданиях | 3 819 | 2 232 |

Precision и recall не сдвинулись. На этом корпусе нужный файл и так находился; изменилось то, что
приходит вместе с ним: на полранга раньше, на 5.9% меньше символов и на 42% меньше строк
исходника, притащенных вместе с ответом. Полная таблица, включая объяснение, почему кейсы называют
файл и не называют символ, — в `docs/codesearch-evaluation.ru.md`.

## Обновление

Устанавливайте GUI-установщиком из этого релиза, затем выполните синхронизацию по каждому
репозиторию. Первая пересоберёт базовое поколение.

Заложите на это время. На том же React-репозитории корпус вырос на 75% — с 3 471 чанка до 6 079,
потому что определение, раньше делившее окно с соседями, теперь получает собственный вектор, — и
пересборка посчитала их примерно за семь с половиной минут. Репозиторий размером с крупное решение
на C# — это порядка часа. `index_status` показывает происходящее как сборку с живым счётчиком и
ETA, чем оно и является: намеренной пересборкой, а не рассинхронизацией.

Больше ничего перезапускать не нужно. Overlay веток пересобираются той же синхронизацией и режутся
по тем же границам, что и базовое поколение, поэтому файл, изменённый в ветке, больше не имеет
формы чанков, отличной от того же файла в основной ветке.

## Проверка

Полное решение прогнало 1 813 тестов: 1 809 пройдено, четыре пропущено по платформенным причинам.

Два из них запускают установленные `scip-typescript` и `scip-python` на фикстурах и проверяют, для
чего каждый сообщает границы тела, — в том числе что scip-typescript не сообщает их для
определения внутри тела функции. Обновление адаптера, меняющее это поведение, уронит тест, а не
сдвинет молча все границы чанков в корпусе.

Ещё два читают исходник самой команды синхронизации и проверяют, что семантическая фаза идёт перед
эмбеддингом — и для базовых поколений, и для overlay. У этого инварианта нет runtime-шва короче,
чем интеграционный прогон с брокером, Roslyn-воркспейсом и обоими внешними индексаторами, а обратная
перестановка блоков читалась бы в ревью как безобидная уборка.

Заодно `codesearch evaluate` перестал падать на любом корпусе, где у всех кейсов есть ответ: доля по
пустому множеству теперь выводится как `null`, а не как NaN, который не является JSON и убивал
прогон уже после того, как все запросы были посчитаны.

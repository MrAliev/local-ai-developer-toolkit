# LocalAi 0.1.52

[English version](0.1.52.md)

Этот релиз — про того, кто читает. Всё, что продукт печатает человеку, теперь приходит на языке
машины, на которой он работает, а всё, что он печатает *программе*, приходит одним
версионированным конвертом, который язык не меняет вовсе. Между этими двумя вещами консоль
получила недостающие команды, индексация перестала перезагружать модель между партиями, а те
части рантайма, которые сбоят, научились записывать, почему.

**Этот релиз ничего не пересобирает.** Границы чанков, семантический формат, контейнер индекса и
модель эмбеддинга не менялись: существующий индекс остаётся действительным, и установка релиза не
запускает пересчёт векторов.

## Всё отвечает на языке, на котором читают

Русская система теперь получает русский везде: инструменты поиска и навигации, вся консоль
`localai`, установщик, ядро индекса, отказы самого брокера. Там, где перевода для языка нет,
ответ английский, и наполовину переведённого не бывает: тест чётности отклоняет релиз, в котором
для языка есть только часть ключей.

Никогда не переводится то, что читает машина или перенабирает человек: команды и их опции,
статусные токены вроде `CONFIGURED`, `STALE` и `INITIALIZING`, значения перечислений,
идентификаторы, пути, форматы обмена и имена полей всех JSON-фигур. Числа, длительности и даты
тоже остаются инвариантными — агенты цитируют такие строки дословно.

Два лица намеренно противоположны. Инструменты MCP следуют за читателем, поэтому один и тот же
отказ одного и того же ядра индекса приходит по-русски через `search_code` и по-английски через
`codesearch search`. Одно читает человек, другое разбирает программа.

## Консоль умеет то же, что инструменты MCP

Вся работа с локальными моделями была доступна только через MCP. Это закрывают четыре команды:

```powershell
localai ask "Одним предложением: что делает этот файл?" src/Foo.cs
localai triage build.log
localai read-image "Что написано на этом экране?" screenshot.png
Get-Content README.md | localai translate --from English --to Russian --out README.ru.md
```

Они идут через ту же очередь брокера, ту же политику резидентности и тот же ограниченный цикл по
фрагментам, что и инструменты MCP, — это не второй путь со своими правилами. У `translate` есть
`--out`, потому что её результат — документ, а не ответ, и каждый перевод несёт абзац с именем
модели, которая его сделала.

Одна команда отвечает, чем вообще можно управлять в каждой консоли:

```powershell
localai capabilities --json
codesearch capabilities --json
```

## Лицо, которое читает программа

`--json` — это второе лицо, и оно одной формы для обоих бинарников:

```json
{"schema":1,"command":"doctor","ok":true,"data":{"verdict":"Ok","failed":0,"warned":0,"checks":[…]}}
```

`schema`, `command`, `ok`, `data`, `error` — плагин пишет один разборщик и для `localai`, и для
`codesearch`. Запрос JSON заодно фиксирует язык английским: версионированный вывод не может
следовать за машиной, с которой он пришёл. Команда, которая `--json` не отвечает, отказывает, а не
печатает прозу, поэтому обещание выполняется без исключений: если флаг передан, в стандартном
выводе конверт.

Сегодня это `localai repo status`, `doctor`, `ask`, `triage`, `read-image`, `translate` и
`capabilities`, а также `codesearch search`, `get-chunk`, `status` и `capabilities`.

Про `doctor --json` стоит сказать отдельно. Он выходит с единицей, когда проверка провалилась, —
это вердикт о машине, — и остаётся `ok: true`, а провалившиеся проверки лежат в `data`, где они и
нужны тому, кто спрашивал о здоровье установки. Каждый факт, который проза называет внутри фразы,
опубликован отдельным полем: идентификатор процесса, глубина очереди, идентификатор поколения,
значения каждой политики. `ok: false` остаётся за запуском, который не дал ответа вовсе.

## Индексация, которая перестала перезагружать модель

Брокер держит модель загруженной, только пока в очереди есть работа для неё, а индексация ставила
следующую партию лишь после ответа на предыдущую — значит, между каждыми двумя партиями очередь на
мгновение пустела, модель выгружалась, и следующая партия начиналась с её загрузки. Замер на одном
репозитории: 3,9 секунды из 11,9-секундной партии и примерно треть всего прогона.

Теперь прогон держит одну партию в полёте, и очередь не пустеет посреди синхронизации. Ни брокер,
ни политика резидентности не менялись: правилу, которое держит модель, пока для неё есть работа в
очереди, просто стало что видеть.

## Когда что-то сбоит, рантайм записывает, что именно

Три вещи, которые происходили молча:

- **Брокер хранит собственные сбои.** `diagnostics.jsonl` в корне рантайма, по объекту JSON в
  строке, ограничен по размеру, с одной ротацией — так первый сбой прогона переживает сотый.
  Раньше они уходили в поток, который никто не читал.
- **Упавшее задание хранит текст отказа.** Фразу, которой ответил бэкенд, — ограниченную по длине
  и очищенную от содержимого запроса — записывают рядом с заданием, несут в исключении, которое
  ловит вызывающая сторона, и пишут в журнал диагностики. Раньше её теряли трижды, оставляя один
  тип исключения.
- **`doctor` отличает занятую очередь от остановившейся.** Очередь, не двигавшаяся два часа,
  выглядела точно как работающая, хотя в файлах состояния уже было всё нужное, чтобы их различить.

`doctor` заодно перестал выдавать за настроенный файл политики, который молча ничего не делает.
Любое хранилище политик отвечает на документ, который не может применить — испорченный, с
неизвестной схемой, со значением вне диапазона, — своими безопасными значениями по умолчанию,
поэтому переставший работать файл оставался на диске и выглядел настроенным. Теперь это
примечание, называющее файл.

## Диск: одно поколение и overlay, которые никто не прочитает

Репозиторий хранил три опубликованных поколения и все overlay, висящие на них. Теперь остаётся
текущее, а поколение, мимо которого указатель уже прошёл, уходит, когда его сменили, а не сутки
спустя, — при этом всё, что ещё *может стать* текущим, сохраняет свою отсрочку, так что уборка во
время сборки не удалит то, что эта сборка производит. Overlay исчезнувших worktree и коммитов, на
которых никого нет, собираются и из остающегося поколения.

`localai prune` заодно перестал заканчивать весь прогон на одной записи репозитория, которую не
смог прочитать, и перестал удалять запись, у которой диск просто отключён.

## Навигация принимает те числа, которые печатает поиск

`search_code` печатает строки с единицы, а инструменты навигации принимали с нуля, и никто между
ними не переводил: вставленная строка попадала на строку вглубь тела — отказ, когда там ничего
нет, и уверенный ответ про чужой символ, когда там что-то было. Теперь оба конца считают с
единицы, и это проверяет сквозной тест: настоящее попадание поиска, переданное в
`go_to_definition` без изменений.

Путь, который не относителен корню репозитория, теперь отклоняется по имени на кромке и на языке
читателя, а не приходит исключением фреймворка по-английски.

## Установщик следует системной теме

Светлая и тёмная палитры берутся из настройки Windows и следуют за ней вживую, и с каждой
страницы мастера есть путь назад.

## Обновление

Ничего, кроме установки, делать не нужно. Раскладка рантайма, формат манифеста и ключ подписи не
менялись, индексы сохраняются, настройки читаются оттуда же.

```powershell
localai update            # откажет, пока у брокера есть задания в очереди
localai update --wait     # сначала дождётся их завершения
```

## Проверка

```powershell
localai doctor
localai doctor --json
```

Первая строка отчёта называет установленную версию; `--json` отвечает то же самое одним конвертом
и теперь несёт `releaseVersion` рядом с каталогом, записанным в указателе.

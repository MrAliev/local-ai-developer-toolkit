# LocalAi 0.1.48

[Русская версия](0.1.48.ru.md)

One fix, found by verifying 0.1.47 on a live machine: the column-0 navigation rule shipped in
that release could never fire for C# — the language it was written for.

**This release does not rebuild anything by itself.** Chunk boundaries, the semantic format
and the generation identity are unchanged, and an existing index stays valid. The fix below
lands in the semantic index's *content*: the next generation build after installing — the
ordinary sync after your next commit — is when column 0 starts resolving on C# lines.

## C# definitions carry their enclosing range

0.1.47 taught column 0 to resolve to the line's outermost declaration by containment over
enclosing ranges. The rule worked — wherever an enclosing range existed. The SCIP importers
carry them through for TypeScript and Python; the Roslyn indexer never wrote one, so for C# a
single-line method signature still declared "two things" with nothing to compare, and column 0
kept degrading to the text heuristic while the identifier column answered Precise.

Definitions produced by the Roslyn indexer now carry the declaration node's full span as
their enclosing range. The spans preserve the sibling guarantee by themselves: each declarator
in `const a = f(), b = g()` spans only itself, and a parameter's node spans only the
parameter, so neither can claim to contain the line. The index format has stored the field all
along — nothing changes shape, and the regression test is end-to-end on purpose: real C#
source through the real indexer into the real resolver, column 0 in, the method out.

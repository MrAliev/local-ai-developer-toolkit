# LocalAi 0.1.32

[Русская версия](0.1.32.ru.md)

One defect, and the reason it was never seen.

## Resolve executables the same way everywhere

npm installs two files for a command on Windows: a POSIX shell script with no extension and a
`.cmd` shim. `File.Exists` is true for the first, and it is not a valid Win32 executable.

`ScipAdapterRunner` was fixed for this in 0.1.24–0.1.27: it matches PATHEXT order and reports
nothing when no shim exists. `StdioLanguageServerClient` kept its own copy of the resolver, which
checked the bare file first — so live navigation on Windows handed back the unstartable script
for any npm-installed language server, which is both of the ones it ships defaults for.

It went unnoticed because live navigation is opt-in and its fixtures skipped whenever the servers
were absent: the same shape as the scip-python failure in 0.1.31 that left every Python
repository unable to publish an index.

There is one `ExecutableResolver` now, with the correct behaviour, used by both. `Find` reports
null when a command cannot actually be run, which is not the same as the file being absent.

## Fixtures find their tools the way the product does

The SCIP and LSP fixtures required an environment variable naming the executable. `scip-typescript`
was installed on the machine this was found on, and its fixture skipped on every run — coverage
that exists and never executes. They now discover tools through the same resolver.

With the language servers installed, the TypeScript SCIP, Python SCIP and pyright paths all run
for the first time.

## Tests in the installer integration project

The project was in the solution, required by `SolutionShapeTests`, and contained no tests. Six
now walk the real view models without installing anything, holding the invariants that survive
any machine: forward moves exactly one place and says so, back returns to the first step, running
is offered on the confirmation page and nowhere else, and an unresolved package says so without
blocking the other steps.

# LocalAi 0.1.47

[Русская версия](0.1.47.ru.md)

Three fixes, all found by verifying 0.1.46 on a live machine: a routed model that failed half
of its jobs invisibly, a navigation shortcut that refused the very hits it was written for,
and a release command whose first real run died inside a Git hook.

**This release does not rebuild anything.** Chunk boundaries, the semantic format and the
generation identity are unchanged; an existing index stays valid, and the navigation fix below
reads spans that index already stores.

## qwen3.5:9b answers instead of thinking its window away

Every technical failure in a month of telemetry — sixteen jobs, 48% of the model's total —
belonged to qwen3.5:9b, and the fallback absorbed each one quietly enough that the pattern
went unnoticed behind acceptable profile-level success rates. The cause: the model reasons by
default, and on the small context tiers routing favours for extraction, classification and
short summaries, the reasoning alone exhausts the window — a full `thinking`, an empty
`content`, a refused response, a fallback.

The routing catalogue now marks models whose reasoning Ollama can switch off, and the broker
sends `think: false` for exactly those — today, qwen3.5:9b alone. gpt-oss cannot have its
reasoning disabled at all, so an unconditional flag would have traded one model's empty
answers for another's refused requests. Native passthrough traffic is untouched.

The month of invisibility was its own defect. `localai telemetry` now prints one plain
`attention` line when a model with enough jobs fails at least a quarter of them and owns at
least half of all recorded failures — the numbers were always in the tables; seeing the
pattern required cross-reading two of them.

## Column 0 navigates to the method, not to a refusal

The bridge from search to navigation promises that a hit's start line navigates as it stands,
with column 0. It was implemented as an exactly-one-declaration rule, and in C# that made the
promise fail for its main audience: a single-line method signature declares the method *and*
its parameters, so column 0 on a method hit fell through to the degradation notice.

A parameter is not a sibling of its method; it nests inside it. Column 0 now resolves to the
declaration whose enclosing range contains every other declaration on the line — a containment
check over spans the semantic index already stores, so the answer keeps its `Precise` label
honestly. A line of genuine siblings (`const a = f(), b = g()`) still refuses, and so does a
line whose would-be container reports no enclosing range: a missing span degrades to the old
refusal rather than to a guess.

## The release command no longer volunteers for Git hooks

The first real run of `release --version 0.1.46` died inside `git switch --create`: the
LocalAi post-checkout hook began synchronizing another worktree's index, and the command's
two-minute Git budget expired measuring an embedding queue rather than Git — after the branch
existed and before the notes were committed. Every Git operation the release command runs now
carries an empty hooks path; the user's next real Git operation still fires the hooks, so the
index does not drift. This release is the fix's first field test: its own preparation ran
end-to-end.

# LocalAi 0.1.33

[Русская версия](0.1.33.ru.md)

One change, finished. Nothing an installed machine does differently — the value every production
path passes is the one it always used.

## A caller can name the runtime root

`RuntimeIndexLayout.Inspect` resolved `%LOCALAPPDATA%\LocalAi` itself, so nothing could ask about
an installation other than the current user's. `CodeSearch.Tests` therefore wrote into the real
runtime. An index build running at the same moment competed with them — and a Git hook fires
`localai sync` synchronously on checkout, so that moment arrives on its own. The loser read as a
flaky test rather than as two things using one directory, which sent more than one investigation
looking for a defect in the product.

Every path that reaches the layout now takes an optional runtime root: `RuntimeIndexLayout`,
`RepoLocator` including the legacy index directory, `SearchService`, `SemanticNavigationGateway`,
`CodeSearchTools`, `CodeSearchSyncCommand` down to its SCIP adapter policy, and
`SemanticNavigationCommand` with all three of its policy stores. The default is unchanged
everywhere and remains the only value production uses.

The tests now each run against a runtime root of their own and delete it. This was checked by
capturing `%LOCALAPPDATA%\LocalAi\repositories` before and after a full run, `legacy` included:
unchanged. `RuntimeIndexLayoutTests` holds that guarantee as a test, so a path that goes back to
resolving the machine's own root fails immediately rather than surfacing later as intermittent
trouble.

An environment variable was considered and rejected. The tests run in parallel inside one process,
and a process has one environment — it would only have rebuilt the same race in a new place.

## Why it shipped in two commits

0.1.32 was cut while half of this was done. Half the paths injected is worse than none, because it
stops being obvious which is intent and which is unfinished, so the incomplete part was held back
rather than released. Both commits are in this release together.

One consequence worth naming: the three `RepoLocator.IndexPathFor` calls inside `SearchService`
were missed the first time, and they alone were enough to keep every test in the real runtime. An
injected root that is not injected everywhere buys nothing at all.

## One definition of the runtime root

`RuntimeIndexLayout` now defers to the definition the rest of LocalAi already shares instead of
spelling out a third copy of `%LOCALAPPDATA%\LocalAi`. Two answers to "which installation" is the
problem the parameter exists to remove.

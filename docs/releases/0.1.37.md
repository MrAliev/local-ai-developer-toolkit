# LocalAi 0.1.37

[Русская версия](0.1.37.ru.md)

Log triage is no longer limited by one model context or by the amount of text that can be read
into memory at once.

## Logs of any length

`triage_log` now accepts exactly one source: an absolute file path or log text supplied directly.
Files are streamed instead of loaded whole. The broker probes the configured contexts from largest
to smallest and uses the largest model/context pair that proves full-VRAM residency on the current
machine.

Every fragment is analysed through the shared FIFO queue, strictly in sequence. Partial findings
are merged by a bounded hierarchical reduction, so the implementation does not retain the whole
log or an unbounded list of summaries. Overlap preserves failures split at a fragment boundary,
while the reducer deduplicates repeated evidence.

## Runtime configuration

The tuning profile is read before every invocation from `log-triage.json` in the LocalAi runtime
root. Operators can cap context and fragment sizes, reserve output capacity, and tune overlap,
partial-summary and character-per-token bounds. Missing, malformed and unsupported policy files
fall back to safe defaults. Editing the file requires neither a rebuild nor a process restart.

The configured context is only a ceiling. It never bypasses the full-VRAM preflight, and failed
larger contexts fall through to smaller catalogued contexts rather than silently spilling into
system memory.

## Upgrading

Install with the GUI installer from this release. The installation restarts the broker and updates
the managed MCP instructions. Existing installations need no configuration; the new defaults take
effect automatically.

## Verification

The complete solution passed 1,766 tests with four platform-dependent skips. A live MCP run
processed 120,087 characters as three sequential fragments at a proved 32,768-token context,
preserved failures at both ends of the input, and left no model resident after completion.

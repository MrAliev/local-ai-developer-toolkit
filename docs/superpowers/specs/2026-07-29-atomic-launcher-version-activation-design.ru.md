# Дизайн атомарной активации версии через launcher

[English version](2026-07-29-atomic-launcher-version-activation-design.md)

## Проблема

LocalAi установлен в неизменяемых каталогах версий внутри
`C:\Users\Mr.Aliev\tools\LocalAi\bin\versions`, но потребители не используют
единый источник активной версии. Codex и Claude запускают CodeSearch и LocalLm
из `versions\caed45c`, а `delegate-to-local-models` запускает устаревший flat
`bin\localai.exe`.

Несовпадение версий воспроизводится только через брокер:

- текущий клиент успешно выполняет `native tags`;
- устаревший клиент получает ответ с `LocalUsageReceipt.Routing`;
- строгая десериализация JSON отвергает добавленное поле, потому что старый
  контракт `LocalUsageReceipt` его не содержит;
- Python-wrapper совместимости превращает ошибку протокола брокера в
  `OllamaUnavailable`.

Обновление нескольких абсолютных путей не является атомарным. Поэтому
перезагрузка или запуск клиента между такими обновлениями может запустить клиент
и брокер разных версий.

## Цели

1. Дать Codex, Claude, wrapper делегирования, Git hooks и ручному CLI единый
   стабильный контракт запуска.
2. Разрешать каждый вызов в одну полную неизменяемую версию LocalAi.
3. Активировать полностью опубликованную версию одной атомарной заменой
   указателя.
4. Запрещать активацию, пока работает вызов предыдущей версии.
5. Не позволять живому брокеру пережить активацию версии.
6. Сохранить единый машинный durable FIFO-брокер и существующий runtime
   `%LOCALAPPDATA%\LocalAi`.
7. Точно различать ошибки launcher, активации и протокола брокера.
8. Мигрировать установленные клиенты и проверить живой broker-only workflow.

## Не входит в задачу

- Прямой вызов Ollama или добавление второго брокера/runtime queue.
- Молчаливое принятие произвольных несовместимых контрактов брокера.
- Перезапись существующего каталога версии на месте.
- Автоматическое изменение посторонних настроек Codex, Claude, Git или моделей.
- Удаление старых каталогов версий во время активации.
- Обновление стабильного launcher при обычной активации версии.

## Архитектура

### Стабильный launcher

Добавляется небольшой executable `LocalAi.Launcher`, зависящий только от базовой
библиотеки .NET. Он не должен ссылаться на assemblies контрактов LocalAi,
брокера, repository, MCP или model routing.

Стабильная установка находится в:

```text
bin\launcher\
  localai-launcher.exe
  localai-launcher.dll
  localai-launcher.deps.json
  localai-launcher.runtimeconfig.json
```

Все долгоживущие регистрации используют launcher:

```text
localai-launcher run localai [arguments...]
localai-launcher run codesearch [arguments...]
localai-launcher run codesearch-mcp [arguments...]
localai-launcher run locallm-mcp [arguments...]
```

Launcher отображает только эти разрешённые имена инструментов в одноимённые
executables выбранного неизменяемого каталога версии. Он передаёт аргументы,
standard input, standard output, standard error, cancellation и exit code
дочернего процесса, не интерпретируя протокол инструмента.

### Указатель текущей версии

Активная версия хранится в `bin\current.json`:

```json
{
  "schemaVersion": 1,
  "version": "caed45c"
}
```

`version` — одно безопасное имя каталога, а не путь. Разрешение отвергает rooted
paths, разделители, `.`/`..`, пустые значения, неизвестные версии схемы, выходы
через reparse point, отсутствующие каталоги и обязательные executables.

Разрешённый каталог обязан оставаться внутри канонического `bin\versions`.
Каталог версии неизменяем после публикации.

### Version lease

`bin\current.lock` координирует запуск и активацию:

1. `run` открывает lease для совместного чтения до чтения `current.json`.
2. Под lease читается и проверяется один snapshot указателя.
3. Запускается точный executable из `bin\versions\<version>`.
4. Shared lease удерживается до завершения дочернего процесса.
5. `activate` требует exclusive access к тому же lease.

Таким образом, активация не может завершиться, пока жив старый CLI- или
MCP-процесс, запущенный через стабильную точку входа. Каждый процесс после
активации видит новый указатель.

### Атомарная активация

Публикация и активация версии разделены. Сначала публикация создаёт и полностью
проверяет новый неизменяемый каталог.

Активация использует:

```text
localai-launcher activate <version> [--stop-running]
```

Операция:

1. Получает машинный activation mutex для сериализации activators.
2. Разрешает candidate внутри `bin\versions`.
3. Без изменения состояния проверяет обязательные CLI, broker, MCP, dependency
   и runtime artifacts. Отдельные broker tests доказывают, что routing catalog
   встроен в `LocalAi.Broker.dll`.
4. С `--stop-running` останавливает только процессы, чей точный executable или
   путь broker assembly принадлежит текущей активной версии LocalAi. Ollama и
   посторонний `dotnet` не останавливаются.
5. С ограниченным timeout получает exclusive version lease.
6. Повторно проверяет candidate после получения lease.
7. Записывает `current.json.tmp` в том же каталоге, выполняет flush и атомарно
   заменяет `current.json`.
8. Повторно открывает и проверяет сохранённый указатель перед сообщением об
   успехе.

Без `--stop-running` активация завершается точной ошибкой `version_in_use`, если
работает дочерний процесс launcher или брокер. При любой ошибке до атомарной
замены прежний указатель остаётся неизменным.

Стабильный launcher не заменяется при обычной активации. Будущее изменение его
контракта будет отдельной maintenance-операцией при отсутствии процессов
launcher.

### Согласованность с брокером

Все новые клиенты запускают broker assembly из собственного физического
неизменяемого каталога версии. Live-миграция останавливает старый брокер до
переключения указателя. После активации первый клиент запускает брокер выбранной
версии под существующим broker startup semaphore.

Брокер остаётся единым для машины и использует существующий runtime root.
Per-version broker и прямой fallback на Ollama не добавляются.

### Регистрация клиентов

`ClientCommand.Plan` регистрирует стабильный launcher и аргументы инструмента
вместо прямых versioned MCP executables:

- Codex `codesearch`: command — launcher; arguments —
  `run`, `codesearch-mcp`.
- Codex `locallm`: command — launcher; arguments —
  `run`, `locallm-mcp`.
- Claude использует эквивалентные command и arguments.
- Git hooks вызывают `localai-launcher run localai`.
- Python-wrapper делегирования вызывает тот же command prefix launcher.

Python `OllamaClient` принимает префикс команды вместо одного hardcoded пути.
Ненулевой exit launcher, невалидный JSON и ошибка протокола брокера остаются
разными ошибками. Stderr брокера попадает в ограниченную и очищенную диагностику,
а не теряется с заменой на `OllamaUnavailable`.

## Поведение при перезагрузке и обновлении

После однократной миграции каждый потребитель имеет стабильную регистрацию.
Публикация новой версии не влияет на работающие процессы. Активация невозможна,
пока работает старый дочерний процесс launcher или старый брокер, а замена
указателя атомарна.

После перезагрузки старых client- и broker-процессов нет. Codex, Claude, hooks и
делегирование могут запускаться в любом порядке, но каждый launcher читает один
сохранённый указатель и запускает binaries из одного неизменяемого каталога.
Существующий broker startup semaphore по-прежнему гарантирует запуск только
одного подходящего брокера.

## Обработка ошибок

Launcher использует стабильные машинные коды ошибок и понятный stderr:

- `current_pointer_missing`
- `current_pointer_invalid`
- `version_path_invalid`
- `version_incomplete`
- `version_in_use`
- `broker_still_running`
- `activation_timeout`
- `child_start_failed`

При ошибке разрешения или активации он завершается с ненулевым кодом, не меняя
указатель. Обычный stdout дочернего процесса не меняется, потому что от него
зависят протоколы MCP и CLI.

## Тестирование

TDD-покрытие докажет:

1. Валидный указатель разрешает каждый разрешённый инструмент в одну версию.
2. Отсутствующий, повреждённый, escaping, reparse-escaping или неподдерживаемый
   указатель отвергается.
3. Неполную версию нельзя активировать.
4. Старый указатель остаётся байт-в-байт прежним после каждой ошибки до commit.
5. Shared run leases блокируют активацию.
6. Конкурирующие activators сериализуются и публикуют один полный указатель.
7. Дочерний процесс продолжает использовать уже разрешённую неизменяемую версию
   после более поздней успешной активации.
8. `--stop-running` выбирает только точные пути LocalAi и никогда не затрагивает
   Ollama или посторонний `dotnet`.
9. Планы Codex, Claude, Git hook и Python используют стабильный launcher.
10. Python различает ошибки process, protocol, timeout и JSON.
11. Существующие broker startup, durable queue и полные solution-тесты остаются
    зелёными.

## Live-миграция и acceptance

Миграция:

1. Публикует проверенную ревизию исходников в новый неизменяемый каталог версии.
2. Устанавливает стабильный launcher без изменения активного указателя.
3. Показывает точный preview процессов и конфигурационных изменений.
4. Останавливает только текущие процессы broker и MCP LocalAi.
5. Атомарно активирует новую версию.
6. Обновляет только существующие записи LocalAi в Codex, Claude, wrapper
   делегирования и установленные LocalAi hooks.
7. Выполняет обычный demand-start клиентов.
8. Проверяет `delegate.py discover`, статус CodeSearch и статус LocalLm через
   общий брокер.
9. Подтверждает, что пути запущенных broker и MCP разрешаются в активированный
   неизменяемый каталог.

Для acceptance не требуется генерация локальной моделью, и Ollama никогда не
вызывается напрямую.

# Проект усиления retrieval в CodeSearch

## Назначение

Реализовать GitHub issue #5 в одной feature-ветке и одном pull request.
Изменение добавляет откалиброванный порог семантической релевантности,
получение чанка для точного snapshot, границы недоверенного содержимого с
nonce и воспроизводимую оценку качества/токенов без замены индексатора и без
обхода LocalAi broker.

## Границы

- Сохранить архитектуру неизменяемой базовой generation и точного overlay
  рабочего дерева.
- Все embedding-запросы оставляются за `BrokerEmbeddingClient` и общим
  долговечным FIFO broker LocalAi.
- Не добавлять прямой доступ к Ollama, второй индекс, межрепозиторный поиск или
  изменения маршрутизации broker, VRAM, offload и политики переводов.
- Выполнять пять инкрементов последовательно. Каждый инкремент должен пройти
  focused-тесты и `dotnet test LocalAi.slnx -c Release --nologo` до начала
  следующего.
- Синхронно обновлять английскую и русскую документацию в одном PR.

## Оценка и калибровка

`tests/CodeSearch.Tests/Fixtures/SearchEvaluation/cases.json` — версионируемый
несекретный корпус из 20–30 случаев: natural-language intent, точные символы,
C#, generic text и несвязанные/no-answer запросы. Каждый запрос с ответом
указывает один или несколько релевантных path/symbol, проверенных по
закоммиченному исходному коду.

Детерминированный evaluator запускает существующий pipeline `SearchService` и
выводит:

- precision@5 и recall@10;
- ранг первого релевантного результата;
- долю false positive для no-answer;
- число символов ответа и строк исходного кода;
- оценку токенов ответа;
- время выполнения, cold/warm классификацию и ожидание очереди broker, когда
  оно доступно;
- число возвращённых файлов/чанков.

Точечная оценка токенов равна `ceil(characters / 4)`, а явный эвристический
интервал — от `ceil(characters / 6)` до `ceil(characters / 3)`. Это инженерная
граница, а не статистический доверительный интервал. Авторитетны сырые числа
символов и строк.

Первый запуск фиксирует текущий baseline без порога. Порог для
`qwen3-embedding:8b-q8_0` выбирается по измеренным распределениям релевантных и
нерелевантных оценок: минимальное значение, которое удаляет все наблюдаемые
векторные false positive для no-answer без снижения recall@10 на запросах с
ответом. Число, версия корпуса, generation ID, число случаев, время запуска и
правило сохраняются в `SearchQualityProfile`. Значение из другой модели или
корпуса не копируется.

## Порог релевантности

`SearchOptions.MinVectorScore` nullable только для явного запуска исторического
baseline без порога в evaluator. Переданное значение должно быть конечным и
находиться в `[-1, 1]`. Обычный production-поиск получает порог из
`SearchQualityProfile` по модели, записанной в индексе.

Неизвестные модели закрываются с диагностикой `threshold not calibrated`.
Только evaluator может явно отключить порог. Векторные кандидаты ниже порога
удаляются до присвоения vector rank для reciprocal rank fusion. Лексические
кандидаты остаются независимыми, поэтому точные символы доступны при пустой
embedding-ветке. Запрос без допустимого векторного или лексического кандидата
возвращает меньше `TopK`, включая ноль.

## Chunk ID точного snapshot

Каждый `SearchHit` получает версионируемый непрозрачный `SearchChunkId`,
содержащий:

- идентичность репозитория;
- ID неизменяемой базовой generation;
- точное дерево HEAD рабочего дерева;
- dirty-content hash при наличии;
- ordinal чанка в composite index.

Сериализованный payload содержит SHA-256 digest целостности. Digest обнаруживает
изменения и повреждения, но не является токеном авторизации. Границей
безопасности остаются разрешённый корень репозитория и проверки точного текущего
snapshot.

`ISearchableIndex` предоставляет идентичность snapshot для `CodeIndex` и
`CompositeIndex`. Composite ordinal детерминирован: чанки overlay идут перед
сохранившимися чанками базы, а ID связан со всеми входами, способными изменить
этот порядок.

`SearchService.GetChunkAsync` разбирает и проверяет ID, определяет текущий
репозиторий и generation базы, заново собирает точный searchable snapshot,
сравнивает repository/generation/tree/dirty, проверяет ordinal и только после
этого читает текущий диапазон строк исходника. Результат содержит path,
start/end lines, kind, symbol, signature и полный текст чанка.

Malformed, integrity-invalid, wrong-repository, stale-generation,
stale-worktree и out-of-range ID имеют разные диагностики. Старый ordinal
никогда не разрешается по новому snapshot.

## Границы недоверенного содержимого

`UntrustedContent.Wrap` создаёт новый 96-битный криптографический nonce для
каждого блока ответа и выводит его в lowercase hex. Если такое представление
уже встречается в содержимом при ordinal case-insensitive сравнении, генерация
повторяется.

Открывающий и закрывающий маркеры содержат nonce. В атрибутах origin
экранируются `&`, `<`, `>`, кавычки, апостроф, carriage return, line feed и tab.
Содержимое сохраняется посимвольно; Unicode-нормализация не выполняется.

`search_code` оставляет доверенный текст индекса/статуса снаружи и оборачивает
каждый блок результата, происходящий из исходного кода. `get_code_chunk`
оборачивает успешный source-derived результат. Ошибки валидации, status и
maintenance output остаются доверенными и не оборачиваются.

## Поток CLI и MCP

- `search_code` возвращает chunk ID и обёрнутые блоки результатов.
- `get_code_chunk` принимает ID и необязательный root и возвращает обёрнутый
  полный чанк.
- CLI search выводит chunk ID.
- CLI evaluation загружает fixture, выполняет baseline или profile режим,
  выдаёт детерминированные JSON-метрики и никогда не обращается к Ollama
  напрямую.

## Проверка

Используются строгие циклы RED → GREEN → REFACTOR. Тесты покрывают валидацию
порога и порядок фильтрации, lexical fallback, нулевой результат, неизвестные
модели, все пути отклонения chunk ID, точный round-trip, враждебное содержимое
и origin, принудительный повтор при коллизии nonce, валидацию fixture, расчёт
метрик и границы форматирования CLI/MCP.

Итоговый A/B-отчёт содержит измеренные baseline/final качество, открытый
исходный код, token proxy, cold/warm latency и ожидание broker, когда оно
выдаётся. Факты, эвристики и недоступные измерения помечаются отдельно.

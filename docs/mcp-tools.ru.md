# Инструменты MCP: полный перечень

[English version](mcp-tools.md)

Двадцать инструментов в двух stdio-серверах. Этот файл — инвентарь: что существует, зачем и
какие ограничения важны. Механизмы описаны в `README.ru.md`, здесь только поверхность,
видимая агенту.

Проверить перечень: `McpToolInventoryTests` в `tests/CodeSearch.Tests`.

## CodeSearch — 11 инструментов

Сервер `codesearch`. Модель эмбеддингов записана в заголовке индекса и не может быть
переопределена в отдельном запросе.

| Инструмент | Назначение | Важное ограничение |
| --- | --- | --- |
| `search_code` | Семантический и лексический поиск по чанкам. Первый шаг для «где живёт X». | C#, TypeScript и Python режутся по символам; остальные языки и любой участок, не покрытый определением, — окном 60 строк с перекрытием 12. Каждый результат обёрнут в `<untrusted-content>`. |
| `get_code_chunk` | Полное тело одного результата по `chunk_id`. | Идентификатор связан с репозиторием, поколением, деревом и dirty-overlay; устаревший отклоняется. |
| `go_to_definition` | Определение символа в заданной позиции. Строка и колонка считаются с нуля, колонка — смещение в UTF-16. | Порядок источников: живой LSP, затем SIDX снимка, затем текст с пометкой `Heuristic`. Позиция, которая сама ничего не называет, разрешается в объемлющее объявление строки — в метод, а не его параметры, — поэтому начальная строка попадания `search_code` годится для навигации как есть, с колонкой 0; объявления-соседи остаются неразрешёнными. |
| `find_references` | Ссылки на символ, позиция задаётся так же. | Тот же порядок источников. |
| `find_implementations` | Реализации, переопределения, производные типы. | Текстового fallback нет: приблизительный ответ здесь хуже пустого. |
| `find_relationships` | Граф связей снимка. | Только SIDX. Направление `incoming`/`outgoing`, вид `implementation`/`override`/`type-definition`. |
| `index_status` | Наличие индекса, модель, размер, отставание от HEAD, фаза синхронизации. | Диагностика — вне границы недоверия. |
| `index_refresh` | Инкрементальное обновление после коммита. | Крупную работу внутри вызова выполнять отказывается и возвращает команду для фона. |
| `index_unload` | Немедленно освобождает память загруженного индекса. | Файл на диске не трогает; следующий поиск перезагрузит его примерно за секунду. |
| `lsp_open_document` | Открывает документ в языковом сервере; он становится авторитетным. | Версии строго возрастают. Живые серверы выключены по умолчанию. |
| `lsp_close_document` | Закрывает документ, возвращая авторитет снимку. | — |

### Языковые серверы

Настраиваются в `language-servers.json`, по умолчанию выключены целиком и по каждому языку.

У адаптера есть `InitializationOptions` — произвольный JSON-объект, который
уходит в LSP-запрос `initialize`. Для `typescript-language-server` это единственный способ
указать tsserver в workspace без собственного `node_modules/typescript`:

```json
"typescript": {
  "Enabled": true,
  "Executable": "typescript-language-server",
  "Arguments": ["--stdio"],
  "InitializationOptions": { "tsserver": { "path": "…/node_modules/typescript/lib/tsserver.js" } }
}
```

Путь задаётся явно и никогда не выводится автоматически: навигация по TypeScript, отличному от
того, которым собирается проект, даёт неправильные ответы, выглядящие правильными. Учтите, что
TypeScript 7 больше не поставляет `lib/tsserver.js`, поэтому подходит установка 5.x.

## LocalLm — 9 инструментов

Сервер `locallm`. Все обращения к моделям идут через общий broker. Четыре инструмента,
работающие с содержимым, — `read_image`, `triage_log`, `ask_local`, `translate_local` —
возвращают ответ модели внутри маркеров `<untrusted-content>` со свежим nonce, а строку notice
оставляют снаружи: локальная модель читала файлы, логи или изображения, и её ответ — такие же
данные, как фрагмент из CodeSearch.

| Инструмент | Назначение | Важное ограничение |
| --- | --- | --- |
| `read_image` | Изображение с диска в текст: скриншот, страница PDF, скан, диаграмма. | Экономит только для изображений, ещё не попавших в контекст. Не больше 8 изображений за вызов, суммарно 60 МБ и 80 мегапикселей. |
| `triage_log` | Машинный вывод любой длины из файла или прямого текста: что упало и почему. | Проверяет наибольший полностью помещающийся в VRAM контекст, затем последовательно разбирает и сводит ограниченные фрагменты. |
| `ask_local` | Механическая задача по известным файлам: перечислить, суммировать, извлечь. | Не для архитектурных решений и тонкого анализа багов. Не больше 64 файлов с общим бюджетом ~720 тысяч символов; лишнее обрезается видимым маркером `TRUNCATED` и называется в notice. |
| `translate_local` | Перевод с проверкой структуры. | Приписывает реальную использованную модель. |
| `local_models_status` | Установленные и резидентные модели, недостающие рекомендованные, состояние экспериментов. | — |
| `local_model_preflight` | Загружает модель и контекст без полезной нагрузки. | Возвращает доказательство полной резидентности в видеопамяти. |
| `local_models_sync` | Ставит установку недостающих моделей в durable-очередь. | — |
| `local_model_experiment_report` | Тайминги, ошибки, fallback, warm/cold, оценка экономии по паре задача/модель. | — |
| `local_model_feedback` | Решение владельца: `Promote`, `ContinueExperiment`, `FallbackOnly`, `Disable`. | — |

`triage_log` перед каждым вызовом читает профиль из
`%LOCALAPPDATA%\LocalAi\log-triage.json` в Windows или
`$XDG_DATA_HOME/LocalAi/log-triage.json` (обычно `~/.local/share/LocalAi/log-triage.json`) в
Linux/macOS. Необязательные поля JSON: `maximumContextTokens`, `reservedContextTokens`,
`charactersPerToken`, `maximumFragmentCharacters`, `maximumOverlapCharacters`,
`maximumPartialSummaryCharacters`, `promptOverheadCharacters` и `schemaVersion: 1`.
Если файла нет, он повреждён или имеет неподдерживаемую версию, применяются безопасные значения
по умолчанию. Изменения вступают в силу со следующего вызова без пересборки и перезапуска.
Ограничение контекста не считается доказательством его вместимости: каждый вызов всё равно
проверяет полную резидентность в VRAM и при необходимости перебирает меньшие размеры из каталога.

### Строка отчёта

Каждый инструмент LocalLm возвращает строку с использованной моделью и оценкой сэкономленных
облачных токенов. Её следует выносить в ответ: смысл в том, чтобы было видно, когда работа ушла
вниз, а не только что она сделана.

Оценка считается из реально обработанного объёма — 4.0 символа на токен для латиницы, 2.2 для
кириллицы, площадь в пикселях делённая на 750 для изображений — и подаётся диапазоном, потому что
живого счётчика токенов здесь нет. Ноль — корректный ответ: задача, слишком мелкая, чтобы что-то
сэкономить, так и говорит.

## Что эти инструменты не заменяют

- **Чтение файла перед его правкой.** Не делегируется никуда.
- **Сплошной поиск по точному токену**, когда цель уже известна: это работа для `rg`.
- **Решения.** Локальная модель 9–27B хороша на «перечисли» и «суммируй»; всё, от чего что-то
  зависит, перепроверяется.
- **Ответ по частичному индексу.** Пока репозиторий индексируется, состояние `INITIALIZING`, и
  это говорится прямо, а не подменяется тихим текстовым поиском.

## Проверка установки

`localai doctor [--root <repo>]` — одна команда вместо последовательности ручных проверок:
версия и целостность её бинарников, стабильная точка входа, живость брокера, очередь и
карантин, действующие политики и состояние индекса репозитория.

Только чтение: диагностика ничего не запускает, в том числе брокер. Ненулевой код возврата
только на настоящую поломку — остановленный брокер помечается как `note`, потому что он
стартует по требованию.

## Что локальные модели на самом деле делали

`localai telemetry` сводит записи, которые брокер пишет для каждого делегированного задания.
Каждая задача оставляет одну запись в runtime root, хранятся они тридцать дней.

Команда отвечает на вопросы, от которых зависит выбор маршрутизации и резидентности: чем
закончились задачи, как часто модель приходилось грузить вместо готовой, как часто срабатывал
fallback, во что реально обошлись очередь и исполнение по медиане и p90 и сколько облачных
расходов удалось избежать — с разбивкой по модели и по профилю задачи. Модель, которая валит
не меньше четверти своих заданий и владеет не меньше чем половиной всех записанных отказов,
называется одной строкой `attention`: fallback прикрывает такую модель достаточно хорошо,
чтобы иначе её не было видно.

Задержки считаются методом ближайшего ранга, поэтому каждая напечатанная величина — это время,
которое действительно заняла какая-то задача. Экономия подаётся диапазоном, а не итогом: оценка
строится по символам, живого счётчика токенов в системе нет, и сумма из ста тысяч оценок точной
не становится.
